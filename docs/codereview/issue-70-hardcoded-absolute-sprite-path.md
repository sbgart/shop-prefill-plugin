# Issue 70 — Абсолютный путь `/wa-apps/shop/img/...` ломает иконки на установках в подкаталоге

**Статус:** ⬜ Открыта
**Приоритет:** 🟠 Средний (у части покупателей плагин выглядит сломанным)
**Сложность фикса:** ⚡ Минутный
**Файл:** `templates/zenmode/ToggleButton.html` (обе ветки, `{if $is_collapsed}` и `{else}`)

## Проблема

```smarty
<use xlink:href="/wa-apps/shop/img/frontend/order/svg/sprite.svg?v{$wa->version(true)}#arrow-bottom"></use>
```

Путь начинается со слэша, то есть отсчитывается от корня домена. Webasyst не обязан стоять в корне: установка вида `https://example.com/shop/` — рабочий и распространённый вариант, и там правильный путь `/shop/wa-apps/shop/img/…`.

Стрелка «Изменить»/«Свернуть» — элемент, который покупатель видит в каждом свёрнутом блоке Zen Mode. При неверном пути `<use>` молча не резолвится: SVG рендерится пустым, кнопка выглядит недоделанной.

Показательно, что в PHP то же место сделано правильно — `shopPrefillPluginZenData::buildPhotosHtml()` строит URL спрайта через `wa()->getRootUrl()`.

## Рекомендация

1. В шаблоне использовать корень приложения, а не корень домена:

   ```smarty
   <use xlink:href="{$wa_url}wa-apps/shop/img/frontend/order/svg/sprite.svg?v{$wa->version(true)}#arrow-bottom"></use>
   ```

   (`$wa_url` доступна во фронтенд-шаблонах Webasyst; альтернатива — передать URL из PHP через `assign`, как это уже делается для `icon_sprite_url` в `CollapseBlock.html`.)
2. Проверить остальные абсолютные пути: `grep -rn 'href="/\|src="/' templates/`.
3. Тест: временно поднять витрину по URL с подкаталогом (или проверить на реальной инсталляции покупателя) — стрелки должны рендериться.
