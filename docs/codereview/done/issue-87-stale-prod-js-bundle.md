# issue-87. Прод-бандл `prefill.frontend.min.js` отстал от исходников и несёт удалённый код

**Статус:** закрыто как неприменимо — 28.08.2026 (в тот же день, что и найдено).
**Было:** 🔴 блокер релиза.

---

## Почему закрыто

Пересборка бандла — обязательный, безусловный шаг 3 `/release-pack` (`.ai/commands/release-pack.md`): вызывается всегда, не по `diff` и не по `git status`. В архив, который реально уходит в стор, попадает `.min.js`, пересобранный из исходников **на момент паковки** — независимо от того, что лежит в рабочем дереве до этого.

Отставание, найденное ниже, — ожидаемое следствие обычной разработки: билд не гоняется после каждой правки JS/CSS-файла из `bundle.config.json`, только на `/release-pack` (сознательное решение, не пробел процесса). Локально это тоже не проявляется — `waSystemConfig::isDebug()` в dev обычно включён, браузер грузит восемь несжатых модулей напрямую, к `.min.js` не обращаясь.

Пункты 1 и 3 из «Что делать» ниже сняты как избыточные: пересборка перед архивацией уже происходит сама, гейт на `mtime` был бы ложной тревогой на каждый обычный `git status` между правками. Пункт 2 остаётся в силе сам по себе (не зависит от staleness — актуален и для идеально свежего бандла) и отслеживается отдельной строкой в `TODO.md` («Прогнать релизный режим R»), дублировать здесь не нужно.

Технические детали находки — ниже, для истории.

---

## Суть

`js/prefill.frontend.min.js` собран **25.08.2026 08:11**. После этого изменились три из восьми входных файлов бандла (`bundle.config.json`):

| файл | mtime |
|---|---|
| `js/modules/ZenModeToggle.js` | 25.08.2026 22:13 |
| `js/modules/OrderFormManager.js` | 25.08.2026 22:14 |
| `js/prefill.frontend.js` | 28.08.2026 12:48 |
| **`js/prefill.frontend.min.js`** | **25.08.2026 08:11** |

Пересборка тем же скиллом (`terser` по `bundle.config.json`) даёт **другой файл**: 13 418 байт против отгруженных 13 690. Бандл не просто отстал — он **больше** пересобранного, то есть содержит код, которого в исходниках уже нет.

CSS-бандл проверен тем же способом и **актуален** (`clean-css` даёт побайтно идентичный `css/frontend.min.css`).

## Что именно лишнее

Диф строковых литералов между отгруженным и пересобранным бандлом:

```
только в отгруженном (устаревшем):  "#wa-step-details-section"  "display"  "style"
только в пересобранном:             —
```

В бандле живёт метод, удалённый из исходников:

```js
forceDetailSectionVisible(){
  const e=$("#wa-step-details-section");
  e.length && e.attr("style") && -1!==e.attr("style").indexOf("display") && e.removeAttr("style")
}
```

И он **не мёртвый** — вызывается из двух мест:

```js
handleFormReady(e){ …this.zenModeToggle.init(), this.zenModeToggle.forceDetailSectionVisible() }
handleDetailsChanged(){ …this.zenModeToggle && this.zenModeToggle.forceDetailSectionVisible() }
```

В текущих исходниках `forceDetailSectionVisible` отсутствует полностью (`grep` по `js/` без `.min.js` — пусто).

## Почему это блокер

Метод — предшественник серверного решения B2b. Сегодня видимостью секции-носителя управляет PHP: `shopPrefillPluginZenMode::generateSectionRevealStyles()` эмитит `display: block !important` **только** когда `shopPrefillCheckoutState::isStepSkipped()` доказал, что ядро шаг не считало, и **только** для свёрнутой группы. Осознанно выключенный администратором шаг под правило не попадает и остаётся скрытым — так решило ядро, и B2b это уважает.

Устаревший JS снимает `style` **безусловно**, на каждом `wa_order_form_ready` и `wa_order_form_details_changed`, не спрашивая ни про `isStepSkipped`, ни про состояние группы. То есть в проде он отменяет ровно то ограничение, ради которого писалось правило: секция, которую ядро спрятало намеренно, будет показана.

## Отягчающее: прод-путь никогда не проверялся в браузере

`shopPrefillPluginAssetsManager::init()` разводит режимы:

- `is_debug === true` → восемь отдельных модулей + неминифицированный контроллер;
- `is_debug === false` → **только** `js/prefill.frontend.min.js`.

Проверено вживую на стенде 28.08.2026 — в `<head>` страницы `/order/` приходят именно восемь модулей:

```
js/modules/HttpClient.js … js/modules/ZenModeToggle.js, js/prefill.frontend.js
```

Значит **все браузерные прогоны из TESTS.md и всех runbook'ов шли по debug-пути, по актуальным исходникам**. Минифицированный бандл — тот единственный файл, который получит реальный магазин, — в браузере не проверялся ни разу.

```bash
cmp js/prefill.frontend.min.js /tmp/rebuilt.min.js && echo ACTUAL || echo STALE
```
