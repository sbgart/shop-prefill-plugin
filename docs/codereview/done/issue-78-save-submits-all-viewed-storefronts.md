# Issue 78 — «Сохранить» отправляет настройки всех витрин, которые администратор успел открыть

**Статус:** ✅ Закрыта
**Приоритет:** 🟢 Низкий (idempotent в норме), 🟠 при параллельном редактировании
**Сложность фикса:** 🔧 Небольшой
**Файлы:** `js/components/prefill-storefront-select.js` (`createStorefrontContainer`, `showStorefrontContainer`), `templates/actions/settings/Settings.html`, `lib/shopPrefill.plugin.php` (`saveSettings`)

## Проблема

Web-компонент кеширует загруженные блоки витрин и **прячет** их, а не удаляет:

```js
hideAllStorefrontContainers(wrapper) {
    …containers.forEach((container) => { container.style.display = "none"; });
}
```

Все эти контейнеры живут внутри `#prefill-storefront-content`, который находится **внутри формы**:

```smarty
<form id="plugins-settings-form" action="?module=plugins&id={$plugin_id}&action=save" method="POST">
    …
    <div class="prefill-storefront-content" id="prefill-storefront-content"></div>
```

Скрытые через `display:none` поля браузер отправляет наравне с видимыми. Имена полей содержат код витрины (`shop_prefill[storefront][<код>][…]`), поэтому в POST уезжают **все** просмотренные витрины, а `saveSettings()` честно сохраняет каждую:

```php
foreach ($settings['storefront'] as $storefront_code => $storefront_settings) {
    …
    $storefront->saveSettings($storefront_settings);
}
```

## Последствия

1. **Потерянные изменения.** Значения в скрытых блоках — снимок на момент их загрузки. Если за это время настройки витрины изменил другой администратор, другая вкладка или debug-эндпоинт `prefill/toggle-zen`, изменения молча откатываются к снимку.
2. **Стоимость сохранения умножается.** `StorefrontSettingProvider::saveSettings()` делает SELECT + INSERT/UPDATE на каждый лист дерева (см. [issue-74 §5](issue-74-minor-findings-pass-2.md)). Открыли 5 витрин — заплатили за 5 полных сохранений.
3. **Побочные записи на диск.** Для каждой отправленной витрины срабатывает `syncCssFile()` → перезапись per-storefront CSS-файла, а `update_time` обновляется → меняется cache-buster → покупатели заново качают CSS витрин, которых никто не трогал.

## Принятое решение

Кеш скрытых контейнеров сохранён намеренно — он не даёт слететь правкам при переключении витрины, сохраняет состояние UI (вкладки, скролл, ace-редакторы) и позволяет править несколько витрин за один заход. Отказались и от автоматического определения изменённых витрин: `sortable()` переставляет DOM без `input`/`change`, ace пишет в textarea через `.val()` — любой флаг «есть изменения» здесь остаётся догадкой, а цена ошибки — молча потерянные настройки.

Вместо этого область сохранения выбирает администратор. Если кроме текущей витрины открыты другие, «Сохранить» показывает диалог: **только текущую витрину** (по умолчанию) или **все открытые** — со списком витрин. При выборе «только текущую» поля скрытых контейнеров отключаются (`disabled`) перед сериализацией и возвращаются сразу после отправки. Предупреждения о перезаписи в диалоге нет намеренно: параллельное редактирование одних и тех же настроек двумя администраторами маловероятно, а текст про потерю чужих правок пугал бы при каждом сохранении.

Бэкенд не изменился: `saveSettings()` с циклом по витринам корректен для ветки «все открытые».

**Реализация:**

- `js/prefill.save-scope.js` — `PrefillSaveScopeDialog` (диалог на `$.waDialog` из Webasyst UI) и `PrefillSaveScope` (перехват сабмита, выбор витрин). Перехват висит на `document` в фазе перехвата: обработчик ядра (`wa-apps/shop/js/backend/plugins.js`) навешен на саму форму, и capture на документе гарантированно раньше. После выбора событие `submit` диспатчится повторно; если его никто не отменил (страница открыта не через SPA плагинов), вызывается нативный `form.submit()`.
- `templates/actions/settings/blocks/SaveScopeDialog.html` — вся разметка и тексты диалога внутри `<template>`; JS только клонирует её и подставляет данные, известные на клиенте.
- `templates/actions/settings/blocks/Head.html` — подключение `wa-content/js/dialog/dialog.{css,js}` (в лейауте настроек плагина их нет).
- `css/prefill.settings.css` — оформление вариантов и списка витрин.
- Локали `dialog.save_scope.*` (ru/en).

Проверено в jsdom (20 сценариев): диалог появляется только при нескольких открытых витринах, «только текущую» отправляет одну витрину и не теряет `_csrf`, «все открытые» отправляет все, отмена не сохраняет, поля возвращаются в исходное состояние (включая поля, отключённые самой формой), fallback на нативную отправку работает.

Проверено в браузере на `wa-dev.loc`: при трёх открытых витринах диалог показывается, при одной — нет. Стороннее изменение настройки глобальной витрины (правка напрямую в БД после её открытия в UI) переживает сохранение с выбором «только текущую» и откатывается к снимку при выборе «все открытые» — то есть ровно то поведение, ради которого заводилась issue.

## Рекомендация (исходная)

1. Перед сабмитом отключать поля скрытых контейнеров:

   ```js
   $('#plugins-settings-form').on('submit', function () {
       document.querySelectorAll('[data-storefront-code]').forEach((c) => {
           const off = c.style.display === 'none';
           c.querySelectorAll('input, select, textarea').forEach((el) => { el.disabled = off; });
       });
   });
   ```

   (`disabled`-поля не отправляются; альтернатива — `cache="false"` на компоненте, но тогда теряется несохранённый ввод при переключении витрины.)
2. Или сохранять по одной витрине через отдельный AJAX-эндпоинт — заодно уходит проблема №2.
3. В любом случае имеет смысл предупреждать при переключении витрины, если в текущей есть несохранённые правки: сейчас они молча уезжают в общий сабмит, и понять, что именно сохранилось, невозможно.
