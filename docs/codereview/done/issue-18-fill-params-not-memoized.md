# Issue 18 — `getFillParams()` не кэшируется внутри провайдера

**Статус:** ✅ Готово  
**Приоритет:** 🟢 Низкий  
**Сложность фикса:** ⚡ Минутный  
**Файл:** `fillparams/shopPrefillPluginFillParamsProvider.class.php`

## Итог анализа

Изначальная проблема в текущей архитектуре не подтверждена как критичная.

- В Webasyst обработчики плагина создаются заново для каждого вызова хука (`new $class(...)` в `waEvent`), поэтому инстанс плагина/провайдера не переиспользуется между `frontend_head` и `checkout_before_auth`.
- Из-за этого memoization полем в `FillParamsProvider` не даст выгоды между хуками и AJAX-запросами checkout.
- Потенциальная польза остается только для редких повторных вызовов в рамках одного request (в основном debug-сценарии).

## Решение

Issue закрыт как **не требующий обязательного код-фикса** в текущем приоритете.  
Если понадобится оптимизация, лучше делать ее на уровне request/session-контекста checkout, а не через локальный кэш инстанса провайдера.
