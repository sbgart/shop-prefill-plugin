# issue-88. `getShippingLogoUrl()` роняет PHP-notice на странице оформления заказа

**Статус:** исправлено 28.08.2026 (в тот же день, что и найдено).
**Приоритет:** 🟠 важно до продажи.

---

## Суть

`shopPrefillCheckoutState::getShippingLogoUrl()`, [строка 565](../../lib/classes/checkout/shopPrefillCheckoutState.class.php):

```php
$variant = $this->getSelectedVariant();
if (empty($variant)) {
    return null;
}

// logo — кастомный из БД (shop_plugin.logo), img — дефолтный из конфига плагина (= icon[48])
return ($variant['logo'] ?: $variant['img']) ?: null;
```

Гард `empty($variant)` защищает от пустого массива, но **не от отсутствия ключей**. Оператор здесь `?:`, а не `??`, поэтому обращение к несуществующему ключу считается ошибкой:

```
Notice: Undefined index: logo
Notice: Undefined index: img
```

Проверено на PHP 7.4.33:

```php
$variant = ["name" => "x"];          // непустой, но без logo/img
$r = ($variant["logo"] ?: $variant["img"]) ?: null;
// TRIGGERED: Undefined index: logo
// TRIGGERED: Undefined index: img
```

## Когда срабатывает

`getSelectedVariant()` возвращает `data.shipping.selected_variant`, а при его отсутствии — `vars.shipping.shipping_rate`. Форма второго определяется **плагином доставки**, а не ядром: сторонние плагины не обязаны класть в тариф ни `logo`, ни `img`. Штатные СДЭК/Курьер/Самовывоз на стенде оба ключа дают, поэтому в наших прогонах notice не всплывал (лог PHP за сессию ревью чист) — но на чужой инсталляции с самописным или редким плагином доставки всплывёт.

Путь горячий: метод зовётся из `renderCollapseBlock()` → `getPluginGroupIcon()` при каждом рендере свёрнутой группы `delivery`, то есть на каждом пересчёте чекаута.

## Почему это важнее, чем кажется

- На PHP 8 это уже не Notice, а **Warning** — а `requirements.php` ограничивает только нижнюю границу (`php >= 7.4`), верхней нет, магазины на 8.x под нас подпадают.
- У части магазинов на дешёвом хостинге `display_errors = On`. Тогда текст ошибки печатается **прямо в HTML страницы оформления заказа**, между секциями формы. Это ровно тот случай, ради которого написано B2a: цена ошибки на пути человека, который уже пришёл оформлять заказ, выше цены невыполненного украшения.
- Плагин в остальном к этому аккуратен — весь соседний код читает `$variant` через `??`. Здесь исключение выглядит опечаткой, а не решением.

## Фикс

Применено в [shopPrefillCheckoutState.class.php:565](../../lib/classes/checkout/shopPrefillCheckoutState.class.php#L565):

```php
return ($variant['logo'] ?? null) ?: ($variant['img'] ?? null) ?: null;
```

Поведение не меняется: `?:` по-прежнему отбрасывает пустую строку, `null` и `0`, — меняется только то, что отсутствие ключа перестаёт быть ошибкой. Проверено `php -r` на всех четырёх исходных кейсах (нет ключей / оба заданы / пустая `logo` / оба `null`) — результат совпадает с ожидаемым, notice не всплывает.
