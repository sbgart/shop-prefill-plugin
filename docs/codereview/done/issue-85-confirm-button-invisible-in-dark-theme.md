# Issue 85 — Кнопка подтверждения в диалоге невидима в тёмной теме витрины

**Статус:** ✅ Закрыта 20.08.2026 — цвет текста переключается вместе со схемой, проверено в обеих
**Приоритет:** 🟠 Средний (покупатель не видит кнопку, на которую его просят нажать)
**Сложность фикса:** 🔧 Однострочный
**Файлы:** `css/frontend.css`, `css/frontend.min.css`

## Проблема

```css
.prefill-dialog__confirm-btn {
    background-color: var(--prefill-accent-color, #000);
    color: #fff;
}
```

Цвет текста прибит к белому, а фон берётся из акцента витрины. Акцент по умолчанию —
`light-dark(#000, #fff)`: в тёмной теме фон кнопки становится **белым**, и белый текст на нём
исчезает. Найдено в браузере на диалоге «Очистить данные формы?» (прогон [issue-64](issue-64-assets-loaded-on-every-page.md)):

```text
.prefill-dialog__confirm-btn → color: rgb(255,255,255), background: rgb(255,255,255)
textContent: "Да, очистить"
```

Кнопка была на месте, кликабельна и работала — не видно было только надписи. Соседняя «Нет»
читалась: у неё обе стороны идут через `light-dark()`.

Задевало любой магазин с настройками по умолчанию.

## Решение

Тот же приём, что уже держит весь остальной диалог, — пара значений на две схемы:

```css
:root {
    --prefill-accent-contrast: light-dark(#ffffff, #000000);
}
```

Кнопка берёт `color: var(--prefill-accent-contrast, #fff)`. В светлой схеме акцент тёмный и
текст белый, в тёмной наоборот. Фолбэк для браузеров без `light-dark()` стоит рядом с уже
существующим фолбэком акцента: там акцент сводится к светлому варианту, а текст — к белому,
то есть к поведению до появления тёмной темы.

Всё, что заливается акцентом, обязано брать текст только из этой переменной — прибивать
цвет в самом правиле нельзя (правило A2).

### Что осознанно не делается

Цвет текста считается от схемы, а не от самого акцента. Магазин, задавший светлый акцент для
светлой схемы (или тёмный для тёмной), получит слабый контраст надписи — но это выбор магазина
в его же настройках, и на умолчаниях плагина такого не возникает. Вычислять контраст из яркости
акцента пробовали — решение не окупает сложности: ради одного правила CSS появлялся PHP-класс,
генерация лишней пары переменных и отдельный тест.

## Проверка

Витрина с акцентами `#c93131` (светлая схема) и `#fff` (тёмная), браузер, 20.08.2026:

| Схема | Фон кнопки | Текст | Итог |
|---|---|---|---|
| Тёмная | `rgb(255,255,255)` | `rgb(0,0,0)` | ✅ читается (было белым по белому) |
| Светлая | `rgb(201,49,49)` | `rgb(255,255,255)` | ✅ читается |

Способ проверки без переключения системной темы описан в [TESTS.md](../tests/TESTS.md) — важно снимать
computed style **следующим кадром** после подмены `color-scheme`.

`css/frontend.min.css` пересобран скиллом `/build-plugin-frontend`.

## Что осталось за рамками

- `.prefill-warning__btn` идёт с классом `button` темы магазина и акцентом не заливается —
  не трогали.
- `.prefill-params__card.is-active` заливается акцентом на 20% через `color-mix`, текст
  наследуется от диалога — контраста хватает.
