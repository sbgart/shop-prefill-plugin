# Issue 32 — Security: cookie `secure=false` в вызовах `setCookie`

**Статус:** ✅ Готово  
**Приоритет:** 🟢 Низкий  
**Сложность фикса:** ⚡ Минутный  
**Файл:** `consent/shopPrefillPluginConsentStorage.class.php`

## Итог анализа

Проблема в исходной формулировке не подтвердилась как уязвимость плагина.

Плагин использует `waResponse::setCookie()`, а в ядре Webasyst:

- при HTTPS автоматически выставляется `SameSite=None` и принудительно `Secure=true`;
- при HTTP используется `SameSite=Lax`, где `Secure` не может дать дополнительной защиты.

Следовательно, плагин не снижает безопасность относительно самого движка.

## Решение

Issue закрыт как **не требующий код-фикса**.  
Рекомендуется только удалить/обновить устаревшие TODO-комментарии про `secure=false`, чтобы не вводить в заблуждение.
