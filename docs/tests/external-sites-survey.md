# Обзор внешних сайтов на Shop-Script — что полезного взять для тест-плана

**Дата:** 28.08.2026
**Зачем:** пользователь дал список реальных работающих интернет-магазинов (свои проекты + портфолио
студии bodysite.ru). Доступ — только как у обычного посетителя витрины, без кода/БД/бэкенда.

## Ограничение метода

Это **не замена браузерным L3-прогонам** из [TEST-PLAN.md](TEST-PLAN.md) — плагин `prefill` на этих
сайтах не установлен, и установить его нельзя (нет доступа к файлам/БД). Ценность только в одном:
это источник **реальных конфигураций Shop-Script-чекаута** (темы, способы доставки, гео-виджеты,
структура полей), которых нет на нашем dev-стенде — то есть материал для расширения матрицы
конфигураций §4 TEST-PLAN.md (в первую очередь K17 — тема, отличная от `default`, и раздел
«8. Совместимость» — S-05..S-08), а не готовые тест-кейсы для самого плагина.

Метод: сначала `curl` по всем доменам на маркеры `wa-data`/`wa-content`/`megashop`/куки
`PHPSESSID`/`shop_cart` — дёшево отсеять, кто вообще на Webasyst/Shop-Script. Затем браузером — по
паре наиболее непохожих сайтов, реально дойти до `/order/` и посмотреть чекаут живьём.

## Важное совпадение с TEST-PLAN.md

Часть сайтов — из портфолио **bodysite.ru**, продавца темы **Megashop**. Это тот же вендор, что
упомянут в TEST-PLAN.md §8 как нерешённый пункт совместимости:

> S-05 | **Плагин `bodysite`** — уточнить точное название и поставить, на стенде отсутствует | ⬜

То есть львиная доля сайтов ниже — живые инстансы именно той темы/экосистемы, которую S-05 просит
завести на стенде. Если когда-нибудь понадобится тема Megashop для K17/S-05 — вот готовый список
живых примеров, как она выглядит в разных нишах.

## Разбор: santeh-city66.ru (дошли до `/order/`)

Реальный чекаут, товар — насос, добавлен в корзину и открыт `/order/`. Отличия от нашего dev-стенда:

- Отдельное поле **«Область доставки»** (`По РФ` и т.п.) **до** «Региона» — вероятно кастомная
  логика поверх ядра, определяющая зону доставки отдельно от гео-адреса. У нас на стенде такого поля
  нет; если когда-нибудь понадобится сценарий с дополнительным полем зоны — вот пример.
- Три типа доставки: «Самовывоз — Екатеринбург», «Пункты выдачи СДЭК, Почта России» (с ценой),
  «Транспортной компанией» (для крупногабарита) — набор шире, чем 3 типа на нашем стенде
  (курьер/самовывоз/почта).
- Промокод (поле + кнопка «Активировать») — функциональность, которой у нас на стенде нет вовсе.
- Бонусная/накопительная программа, видна прямо в корзине («+710.44 бонусных баллов»).
- БНПЛ/рассрочка: «Покупка в кредит» через Тинькофф/Сбербанк/Халва — на нашем стенде способов
  оплаты меньше и без рассрочки.
- «Пользуйтесь подсказками» у поля «Город» — судя по всему автокомплит по городам (кандидат на
  gео-плагин помимо cityselect/regions, которых у нас на стенде их два).
- Cross-sell карусель «Рекомендуем» прямо на странице корзины (не только во всплывающем окне после
  добавления товара) — у нас на стенде такого блока нет.

## Разбор: gangga.ru (дошли до `/order/`)

Другая ниша (товары для здоровья), другой набор виджетов:

- **Попап геолокации на главной** — «Ваш город Москва? Да/Нет» с первого экрана. Прямой аналог
  сценария H-01 (ФО-08, «окна "Ваш город?"») — только это не наш `SeoRegions`/`cityselect`, а
  собственный виджет темы/магазина. Полезно как визуальная референс-точка: как в принципе выглядит
  этот паттерн у конкурентов/других тем.
- Форма покупателя с полем **«Отчество»** отдельно от «Имя»/«Фамилия» — у нас на стенде такого поля
  нет; если в бэклоге когда-то встанет вопрос про отчество в auth-секции — вот живой пример разметки.
- Геосекция чекаута проще, чем у `santeh-city66.ru`: только «Страна» + «Город» (с подсказками) +
  «Индекс», без отдельного «Региона» — то есть у Shop-Script это конфигурируемо per-магазин
  (`address_fields`), не одна и та же форма везде.
- Четыре типа доставки, включая «Курьер до двери (СДЭК)» **отдельно** от самовывоза ПВЗ СДЭК — более
  тонкая грануляция типов доставки одной службы, чем на нашем стенде.

## Не проверялось / технические затруднения

- `sexshop-xl.ru` — сознательно не открывался браузером, curl тоже не делался; ниша сама по себе не
  даёт технической причины её избегать, просто не было необходимости для целей этого обзора.
- `a12.ru` — не отвечает (`HTTP:000` дважды подряд), недоступен в момент прогона.
- `awstroy.ru` — за анти-бот защитой хостинга (Beget), `curl` получает JS-челлендж вместо страницы.
- `ipilot.store` — единственный явно **не-Webasyst** сайт в списке, несмотря на присутствие в
  портфолио bodysite; дальше не смотрели.
- Остальные 20 сайтов из «Итоговой таблицы» проверены только `curl`-триажем (подтверждён факт
  Shop-Script/Megashop), без захода в каталог/корзину браузером — этого достаточно для вывода
  «на чём написано», но не для содержательного сравнения UX чекаута.
