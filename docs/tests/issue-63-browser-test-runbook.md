## Грабли, которые уже стоили времени

- Товар в корзину кладётся **только со страницы товара**; кнопка «В корзину» в списке на главной не срабатывает.
- Город **автозаполняется** после выбора региона — не вводить следом руками, получится «МоскваМосква».
- «Индекс» и «Подъезд» обязательны даже для самовывоза. Самовывоз открывает модалку выбора ПВЗ.
- Заказ оформляется полной перезагрузкой на `/checkout/success/`.
- Бэкенд и витрина — **одна сессия**: залогинен в бэкенде → на витрине не гость.
- Выход **покупателя** (`is_user = 0`) по URL не работает. Приём: `UPDATE wa_contact SET password = CONCAT(password,'x') WHERE id = <ID>;` → на следующем запросе токен рассинхронизируется и `clearAuth()` сделает гостя.
- Куки плагина **HttpOnly**, из JS не видны, `Set-Cookie` браузерные инструменты не отдают → факт выдачи куки проверять **по логу плагина на сервере**.
- В SPA настроек селектор витрины — web-компонент: менять через `form_input` по внутреннему `<select>`, значение = base64 кода витрины. После переключения старый DOM остаётся — брать `querySelectorAll(...).pop()`, не `querySelector`.
- Радиокнопки `order_without_auth` визуально скрыты (0×0) — кликать по `<label>`.

## Инструмент 1: точный подсчёт SQL за запрос

Проверено — работает на этой установке.

```bash
# включить
MY -e "SET GLOBAL log_output='TABLE'; SET GLOBAL general_log='ON'; TRUNCATE TABLE mysql.general_log;"

# ...сделать ровно одно действие в браузере (одна загрузка страницы)...

# что выполнялось по интересующим таблицам, с разбивкой по соединениям
MY -e "
SELECT thread_id, event_time, LEFT(CONVERT(argument USING utf8mb4), 160) AS q
FROM mysql.general_log
WHERE command_type='Query'
  AND argument REGEXP 'shop_order_params|shop_order|shop_customer|wa_contact'
ORDER BY event_time;"

# сводка: сколько запросов к заказам за это действие
MY -e "
SELECT COUNT(*) AS order_queries
FROM mysql.general_log
WHERE command_type='Query'
  AND argument REGEXP 'shop_order_params|shop_order |shop_customer';"

# выключить и прибрать (ОБЯЗАТЕЛЬНО в конце сессии)
MY -e "SET GLOBAL general_log='OFF'; SET GLOBAL log_output='FILE'; TRUNCATE TABLE mysql.general_log;"
```

Исходные значения на этой машине: `general_log = OFF`, `log_output = FILE`. Вернуть именно их.

Одна загрузка страницы = одно PHP-соединение = обычно один `thread_id`; при сомнении группировать по нему. Лог ловит **все** приложения, поэтому фильтр по именам таблиц обязателен.

## Как получить чистую сессию (проверено 18.08.2026)

Главная сложность прогона: `PHPSESSID` — HttpOnly и сеансовая, файлов сессий на диске нет,
уничтожить сессию извне нечем. Про логаут: 18.08.2026 `webasyst/?action=logout` **очистил**
`shop/checkout` (форма после него пустая, ссылки «Мои варианты» нет), но полагаться на это
как на способ сброса не стоит — он меняет ещё и личность, а значит и source key. Рабочий рецепт:

1. Войти в бэкенд (`https://wa-dev.loc/login/` — пароль подставляет браузер, только нажать «Войти»).
2. Из **витринной** страницы дёрнуть два эндпоинта:
   ```js
   await fetch('/prefill/clear-storage', {method:'POST'});   // shop/checkout + маркер
   await fetch('/prefill/reset-snapshot', {method:'POST'});   // shop/prefill_snapshot
   ```
3. При необходимости выйти — гостевая кука `prefill_guest_token` живёт год и переживает логаут.

**Для гостевых сценариев вход не нужен вовсе** (найдено 18.08.2026). Публичный эндпоинт
`/prefill/consent` с `action=clear_form` снимает ровно то, что мешает, и сохраняет токен:

```js
await fetch('/prefill/consent', {method:'POST',
  headers:{'Content-Type':'application/x-www-form-urlencoded'}, body:'action=clear_form'});
```

Он удаляет `shop/checkout`, `shop/prefill_snapshot` и маркер `shop/prefill_source`, но **не трогает**
куку `prefill_guest_token` — то есть даёт чистую сессию тому же гостю. Именно так проверяется, что
загрузчик реально сходил в БД: пока цел снапшот, он не вызывается вообще (ленивый по замыслу),
и подсчёт запросов покажет ноль не потому, что что-то сломано.

Не путать с `action=clear` и `action=revoke` — те зовут `forget()` и **уничтожают** токен вместе
со строками `prefill_guest_%` в заказах.

Оба эндпоинта закрыты `isDebug() && isAdmin('shop')`, поэтому вход обязателен.
`/prefill/consent` (действия `clear`, `revoke`, `clear_form`) — публичный.

Завершающий слэш роли не играет: 18.08.2026 в `lib/config/routing.php` добавлен суффикс `/?`
ко всем роутам плагина, как в ядре. До этого адрес со слэшем отдавал 404.

Ещё грабли: `javascript_tool` иногда блокирует `fetch` ответом `[BLOCKED: Cookie/query string data]`.
Помогает возвращать из скрипта короткую строку статуса, а не тело ответа.

Побочно подтверждено на этом же прогоне:

- **Ленивость загрузчика.** Сразу после оформления заказа `/order/` восстановил все шесть секций
  из снапшота и не сходил в БД **ни разу** — загрузчик не вызывался вообще.
- **Гостевой цикл целиком.** Заказ 89 → `Guest token created` + `Guest order link saved`;
  следующий заход предзаполнил форму данными этого заказа.
- **Маркер сбрасывается после заказа** (`OrderHooks` → `clearSourceMarker()`), поэтому следующий
  визит подхватывает свежий `order_id`.

### Что осталось непроверенным

- 4.5 (ручной ввод не перетирается) и 4.7 (`cityselect`) — в этот прогон не входили.
- Фаза 0 (baseline «было») не снималась: реализация к моменту прогона уже была в коде.
