## Итог

**R-04 (чистая установка) — ✅.** Веб-инсталлятор Webasyst отработал без ошибок, распаковал все
приложения и плагины (включая prefill — виден в логе распаковки), создал администратора, автоматически
завёл Shop-Script с демотоварами. Плагин `prefill` сразу оказался в списке «УСТАНОВЛЕНЫ» (Webasyst сам
регистрирует найденные в `wa-apps/{app}/plugins/` папки при первой загрузке приложения — отдельного шага
«установить» через UI не потребовалось). Таблица `shop_prefill_settings` создана (`SHOW TABLES` ✅), но
**пустая** (0 строк) — это не баг: настройки читаются из `lib/config/settings.php`/`storefront.settings.php`
как чистые PHP-дефолты и пишутся в БД только при явном сохранении администратором (тот же паттерн, что
описан в CLAUDE.md про строку `storefront_code='-'`). Настройки плагина (SPA, все 4 вкладки и 6 категорий)
открылись без ошибок. Чекаут (`/shop/order/`) отработал сразу же — добавление демотовара в корзину,
переход в оформление, поля формы отрендерились корректно. По умолчанию плагин **не активен** ни на одной
витрине (`storefront.settings.php: 'active' => false` для конкретной витрины) — это осознанный дефолт,
require явного включения администратором, а не баг «ничего не подставляется». PHP/Apache-лог — чисто, 0
ошибок и warning.

**R-07 (удаление) — ✅, со значимой находкой по методологии Docker-стенда.** Первые ~8 попыток удалить
плагин через UI («...» → «Удалить плагин» → confirm-модалка → «Удалить») не сработали: файл/таблица
оставались на месте. Разбор показал **два наложившихся эффекта**:

1. **Артефакт этого конкретного стенда, не баг платформы.** `installerHelper::isDeveloper()`
   (`wa-apps/installer/lib/classes/installerHelper.class.php:250`) проверяет `$root_path.'/.git'` — если
   каталог `.git` существует в корне инсталляции, ядро считает это «версия для разработчика» и **отказывает
   в удалении** любого плагина/темы/виджета («Plugin not deleted: .svn or .git folder located in the plugin
   directory»), это защита от случайного удаления рабочей git-копии через UI. Стенд был собран через
   `git clone` (`webasyst-framework` в корень, `shop-script` в `wa-apps/shop/`) — оба клона оставили `.git`,
   что и включило эту защиту сайт-вайд. Решение: `rm -rf www/.git www/wa-apps/shop/.git` после клонирования
   (либо `git archive` вместо `git clone` для обеих частей). После удаления `.git` — сервер-сайд запрос
   `POST /webasyst/installer/assets/?module=plugins&action=remove` (именно этот эндпоинт вызывает клиентский
   JS) сразу отработал: 302 → `?msg=...` с сообщением об успехе, папка `wa-apps/shop/plugins/prefill`
   и таблица `shop_prefill_settings` исчезли за один запрос.
2. **Побочно найдено (не влияет на итог, отдельная любопытная деталь):** на пути к разгадке п.1 несколько
   попыток клика по «Удалить плагин» в браузере на этой сборке (4.2.0) заканчивались JS-исключением
   `TypeError: $.waDialog.confirm is not a function` (`wa-system/plugin/templates/Plugins.html:232`,
   `wa.dialog.js` этой версии core действительно не содержит метода `confirm`). Не расследовалось до конца,
   останавливает ли это модалку каждый раз или только в части случаев (модалка иногда всё же рисовалась) —
   не наш код (`wa-system/plugin/`, общий для всех приложений, не специфично для shop/prefill), в отчёт
   вносится как наблюдение для истории, не как находка о prefill.

Проверка после удаления: `wa-apps/shop/plugins/` — 14 записей (было 15, минус prefill, ничего чужого не
пострадало), `shop_prefill_settings` отсутствует в `SHOW TABLES`, `wa-data`-файлов у плагина не было (не
активировался на этой витрине, см. R-04), явных `wa-cache`-огрызков (`shop_prefill`, `shop.prefill`) не
чистилось отдельно — это кэш скомпилированных шаблонов/локалей, штатно инвалидируется, не то же самое, что
"файлы wa-data" из критерия. Чекаут (`/shop/order/`) после удаления отработал **стоково**, без ошибок в
логе (проверено `docker compose logs php` за весь прогон — 0 `error`/`warning`, не считая штатного
`AH00558 ServerName` при старте Apache).

## Вывод

R-04 и R-07 из §9 TEST-PLAN.md закрыты живьём. Единственная методологическая находка — для будущих

и создаёт ложное впечатление бага платформы.
