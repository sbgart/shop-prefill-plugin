# Тестирование системы предзаполнения

## Цель

Проверить работу системы предзаполнения с новой архитектурой:
- Для авторизованных: данные из БД по `contact_id`
- Для гостей: данные из БД по хешу `prefill_guest_hash`

## Дебаг функционал

Для отладки используется класс `shopPrefillPluginDebug` (находится в `lib/classes/debug/`):

- Летающее окно с информацией о состоянии хранилища
- Метаданные об источнике данных (order ID, guest hash, contact_id)
- Количество заказов пользователя

## Как протестировать

### 1. Включите режим отладки

В файле `wa-config/SystemConfig.class.php` установите:

```php
public static function isDebug()
{
    return true;
}
```

### 2. Тестовые сценарии

#### Сценарий 1: Неавторизованный пользователь (первый заказ)

1. Откройте Incognito режим браузера
2. Добавьте товар в корзину и перейдите к оформлению
3. В дебаг окне проверьте:
   - `user_authorized: false`
   - `guest_hash: abc123...` (короткая версия хеша)
   - `orders_count: 0`
   - `source: empty (no orders)`
4. Оформите заказ
5. Снова добавьте товар и перейдите к оформлению
6. Проверьте дебаг окно:
   - `orders_count: 1`
   - `source: order`
   - `source_order_id: <ID заказа>`
   - Данные предзаполнены из последнего заказа

**Ожидаемый результат:**

- После первого заказа данные предзаполняются из БД
- Хеш гостя сохраняется между визитами (cookie 1 год)

#### Сценарий 2: Авторизованный пользователь

1. Авторизуйтесь на сайте
2. Добавьте товар и перейдите к оформлению
3. В дебаг окне проверьте:
   - `user_authorized: true`
   - `contact_id: <ID пользователя>`
   - `guest_hash: null`
   - `orders_count: <количество заказов>`
4. Если есть заказы:
   - `source: order`
   - `source_order_id: <ID последнего заказа>`

**Ожидаемый результат:**

- Данные берутся из последнего заказа по `contact_id`
- Хеш гостя не используется для авторизованных

#### Сценарий 3: Несколько заказов гостя

1. Incognito режим
2. Оформите заказ с адресом А
3. Оформите заказ с адресом Б
4. Третий раз добавьте товар → чекаут
5. Проверьте:
   - `orders_count: 2`
   - Предзаполнен адрес Б (из последнего заказа)

**Ожидаемый результат:**

- Все заказы привязаны к одному хешу гостя
- Предзаполняются данные из последнего заказа

#### Сценарий 4: Менеджер исправил заказ

1. Оформите заказ с адресом "ул. Ленина, 1"
2. В админке измените адрес на "ул. Ленина, 10"
3. Добавьте товар и перейдите к чекауту
4. Проверьте предзаполненный адрес

**Ожидаемый результат:**

- Предзаполнен исправленный адрес "ул. Ленина, 10"
- Данные всегда берутся из БД (актуальные)

## Проверка в БД

### Найти хеш гостя в заказах

```sql
SELECT order_id, value 
FROM shop_order_params 
WHERE name = 'prefill_guest_hash' 
ORDER BY order_id DESC 
LIMIT 10;
```

### Найти все заказы по хешу

```sql
SELECT op.order_id, o.create_datetime, o.total 
FROM shop_order_params op
JOIN shop_order o ON o.id = op.order_id
WHERE op.name = 'prefill_guest_hash' 
  AND op.value = '<hash>'
ORDER BY op.order_id DESC;
```

### Проверить cookie

В браузере (DevTools → Application → Cookies):
- Имя: `prefill_guest_hash`
- Значение: SHA256 хеш (64 символа)
- HttpOnly: true
- Expires: через 1 год

## После тестирования

1. **Отключите debug режим** в `SystemConfig.class.php`
2. **Очистите тестовые заказы** (опционально)

## Ожидаемые результаты

| Сценарий                | Источник данных  | Актуальность          |
| ----------------------- | ---------------- | --------------------- |
| Гость, первый заказ     | Пусто            | —                     |
| Гость, повторный визит  | БД по хешу       | Всегда актуально      |
| Авторизованный          | БД по contact_id | Всегда актуально      |
| Менеджер исправил заказ | БД               | Изменения применяются |
