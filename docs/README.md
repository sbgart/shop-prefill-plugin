# Документация плагина Prefill

Добро пожаловать в документацию плагина Prefill для Shop-Script!

## 🚀 Быстрый старт

### Компиляция локализации

После изменения файлов переводов всегда выполняйте компиляцию:

```bash
cd /Users/user/Project/wa-dev
php wa.php locale shop/plugins/prefill
```

### Очистка кэша

Если изменения не видны, очистите кэш:

```bash
# Кэш локализации
rm -f wa-cache/*/apps/shop_prefill/locale/*.php

# Весь кэш плагина
find wa-cache -name "*.php" -path "*/shop_prefill/*" -delete
```

### Локализация в JavaScript

Для использования переводов в JS, они должны быть явно переданы через шаблон:

```smarty
<script>
  var $_locale = {
    'Error': "{'Error'|_wp|escape:'javascript'}",
    'error.message': "{'error.message'|_wp|escape:'javascript'}"
  };
  window.$_ = function(key) {
    return $_locale[key] || key;
  };
</script>
```

Подробнее: [LOCALIZATION.md](guides/LOCALIZATION.md)

## 🗂️ Куда писать документацию

### Для ИИ-помощников: правила размещения документов

При создании новой документации следуйте этим правилам:

#### 📖 Руководства и гайды → `guides/`

Создавайте файл в `guides/`, если это:

- Пошаговое руководство по использованию функции
- Инструкция по настройке или конфигурации
- Объяснение процесса (релиз, локализация и т.д.)
- Справочник по API или архитектуре

**Формат имени:** `НАЗВАНИЕ-ТЕМЫ.md` (заглавными буквами)

#### 💡 Идеи и предложения → `ideas/`

Создавайте файл в `ideas/`, если это:

- Предложение новой функциональности
- Экспериментальный подход к решению задачи
- Черновик будущего улучшения
- Обсуждение возможных изменений

**Формат имени:** `краткое-описание-идеи.md` (строчными буквами)

#### 📋 Задачи в разработке → `todo/`

Один файл на задачу. В [TODO.md](TODO.md) — только строка вида `- [ ] **[Название](todo/файл.md)**`. Детали — в файле.

#### 🐛 Баги и проблемы → `bugs/`

Создавайте файл в `bugs/`, если это:

- Обнаруженный баг, требующий детального анализа
- Проблема, которая не может быть исправлена немедленно
- Известная проблема с workaround
- Баг, требующий обсуждения подходов к исправлению

**Формат имени:** `краткое-описание-бага.md` (строчными буквами)

**Структура документа:**
```markdown
# Название бага

**Статус:** [Открыт / В работе / Исправлен]

## Описание
Что происходит не так

## Воспроизведение
Шаги для воспроизведения

## Ожидаемое поведение
Как должно работать

## Фактическое поведение
Как работает сейчас

## Возможные решения
Варианты исправления
```

#### 📝 Концепция и техдокументация → `concept/`

Общая концепция, техспецификация, архитектура, валидация и бизнес-логика.

#### 🚀 Релизы → `releases/`

Размещайте в `releases/`, если это:

## 🐛 Решение проблем

### Отображается ключ вместо перевода

1. Скомпилируйте переводы: `php wa.php locale shop/plugins/prefill`
2. Очистите кэш: `rm -f wa-cache/*/apps/shop_prefill/locale/*.php`
3. Проверьте загрузку локализации в action:
   ```php
   waLocale::loadByDomain(array('shop', 'prefill'));
   waSystem::pushActivePlugin('prefill', 'shop');
   ```

### JavaScript показывает ключи локализации

1. Проверьте передачу переводов в шаблоне (см. [LOCALIZATION.md](guides/LOCALIZATION.md))
2. Убедитесь, что скрипт с `$_locale` загружается ДО основного JS
3. Проверьте в консоли: `console.log($_("Error"))`

### Изменения не отображаются

1. Очистите кэш плагина
2. Очистите кэш браузера (Ctrl+Shift+R)
3. Проверьте версию файлов (должен меняться query string `?v{$plugin_version}`)
