# План пересъёмки скриншотов витринного описания

## Цель

Заменить четыре изображения, используемые в `store-description-preview*.html`, на единый правдоподобный сценарий повторной покупки. Не использовать данные администратора, технические пункты меню или случайные демо-товары как главный визуальный материал.

## Единая фикстура

- Отдельный тестовый покупатель с вымышленными, но естественными русскими данными; не изменять контакт `Admin`.
- Город: Новосибирск.
- Доставка: активный пункт выдачи СДЭК из текущей локальной витрины; выбранный пункт должен быть виден в checkout и в диалоге «Мои варианты доставки».
- Оплата: наиболее понятный из уже активных методов витрины. Не устанавливать новый платёжный плагин ради скриншота; если нет онлайн-оплаты, оставить «Наличные при получении» с понятным названием.
- Корзина: один или два товара с естественными названиями и суммой, без технических суффиксов «(демо)» в видимой области кадра.

| `checkout-zen-focus.png` | Компактная сводка Дзен-режима | Покупатель, СДЭК, оплата, «Изменить», итог; без отладочной панели |

| `account-orders-focus.png` | Постоянная авторизация | Имя покупателя рядом с аватаром, «Мои заказы», 1–3 заказа; осмысленная навигация без «Пустышка» |

## Порядок работы

1. Проверить активные на витрине способы доставки и оплаты, выбрать фактически доступные варианты.
2. Создать отдельного тестового покупателя и его историю заказов, не меняя администратора и существующие тесты.
3. В браузере подтвердить каждый из четырёх состояний: предзаполнение, Дзен-сводку, диалог вариантов и личный кабинет.
4. Снять исходники с запасом по краям. CSS презентации кадрирует их и добавляет перспективу, поэтому важные заголовки и элементы управления не должны лежать у границ.
5. Заменить только четыре используемых PNG, проверить светлую и тёмную тему HTML-превью, сохранить предыдущие изображения отдельно до финального согласования.

## Handoff для новой задачи

### Что уже готово

- В глобальную конфигурацию Codex добавлен официальный `playwright` MCP (`npx -y @playwright/mcp@latest`). В новой задаче сначала проверить, что доступен `browser_take_screenshot`; сохранять кадры через его `filename`, а не через UI или Preview.
- На локальной витрине создан отдельный тестовый покупатель **Елена Воронцова**. Учётные данные намеренно не записаны сюда; не использовать и не изменять контакт `Admin`.
- Создан локальный тестовый заказ **#100130**: ПВЗ **СДЭК — Новосибирск, Вокзальная магистраль (NSK2)**, товар **«Люстра шар 12-ти рожковая (белый)»**, сумма 3 000 ₽.
- На реальном checkout подтверждены: выбор ПВЗ СДЭК и доступная **ЮKassa** (карта, СБП, SberPay, T-Pay). Для исторического заказа выбрана безопасная оплата при получении, чтобы не открывать внешний платёжный шлюз.

### Что сделать дальше

1. Войти тестовым покупателем или использовать сохранённую сессию, закрыть панель «Диагностика Prefill» и положить в корзину товар без «(демо)».
2. Получить и сохранить четыре исходных PNG: `checkout-filled-closeup.png`, `checkout-zen-focus.png`, `delivery-variants-focus.png`, `account-orders-focus.png`.
3. В checkout-кадрах показать Елену, выбранный ПВЗ СДЭК, ЮKassa и итог. Для диалога оставить видимыми заголовок и крестик, а также 1–2 карточки СДЭК.
4. В личном кабинете показать имя «Елена» рядом с аватаром и заказ #100130. Не включать в кадр технические пункты навигации `Пустышка`/`Dummy` — кадрировать шапку или предварительно подготовить осмысленное меню.
5. Подменить только эти четыре используемых ассета в `docs/marketplace-assets/screenshots/current/`, затем открыть `docs/marketplace-assets/description/previews/store-description-preview-rounded.html` и проверить светлую и тёмную темы.

### Не делать

- Не записывать пароль тестового покупателя в код, документы, логи или сообщения.
- Не менять текст презентации, `Admin` и существующие пользовательские изображения вне четырёх файлов.
- Не использовать Orca для браузерной автоматизации.
