# E-08 не прогнан живьём: вариант доставки из истории, недоступный на текущем адресе

**Статус:** ⬜ Не найден баг — сценарий не прогнан, фикстура не заводится на этом стенде
**Приоритет:** 🟠 (сценарий из ФО-05, P8/B2a — но не найденный дефект, а непокрытая ветка)

## Сценарий (E-08, ФО-05 TEST-PLAN.md)

Покупатель открывает «Мои варианты доставки», выбирает вариант из истории заказов, который для его
**текущего** адреса больше не обслуживается (например, ПВЗ закрылся, зона доставки сузилась). Ожидание:
диалог «доставка недоступна», форма не ломается.

## Почему не прогнан 12.09.2026

`FrontendApplyDeliveryController` сам не валидирует доступность варианта — он только пишет адрес/вариант в
сессию (`SessionStorageProvider::applyDeliveryAddress()`); реальная проверка происходит на стороне ядра
при пересчёте (`shopCheckoutShippingStep`, сверяет `variant_id` с заново посчитанным списком). Значит,
чтобы прогнать E-08 честно, нужен вариант, который ядро/сторонний shipping-плагин **реально отклонит**,
а не искусственно смоделированная ошибка на стороне prefill.

Пробовал воспроизвести на реальных данных: у admin есть заказ #134 с редким ПВЗ `43.NSK43:136:270`
(Гусинобродское шоссе, Новосибирск) — отличается от обычного `NSK2:136:270` в остальных заказах. Проверил
справочник стороннего shipping-плагина `wa-plugins/shipping/sydsek` (таблица
`wa_shipping_sydsek_pickups`) — оба ПВЗ (`NSK2`, `NSK43`) по-прежнему существуют, органической
недоступности из истории нет.

Чтобы всё-таки её получить, пришлось бы вмешаться в данные/конфигурацию чужого плагина (отключить ПВЗ,
урезать зону обслуживания СДЭК) — это уже тестирование стороннего плагина, а не prefill. Решил не идти
этим путём: риск ложного результата от неправильно смоделированной чужой недоступности выше пользы.

## Как можно закрыть в будущем

- Дождаться, пока в реальной истории заказов появится вариант, чья зона/ПВЗ действительно перестанет
  обслуживаться (естественная фикстура) — тогда прогнать сценарий на живых данных.
- Либо на одноразовом Docker-стенде (см. `~/Project/shop-fresh-docker` в TEST-PLAN.md §7) сознательно
  сконфигурировать простой встроенный способ доставки (например, «Курьер» с фиксированной зоной страна/
  регион/город) так, чтобы текущий адрес заведомо выпадал из зоны, и историческую попытку выбрать такой
  вариант — тогда недоступность будет честной и не потребует правки данных стороннего плагина.
