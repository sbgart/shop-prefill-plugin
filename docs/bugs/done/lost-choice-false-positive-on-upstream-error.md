# Диалог «Нужно выбрать другую доставку» показывается при любой ошибке авторизации или региона

**Статус:** ✅ Найдено 04.10.2026 при прогоне 1.0.0, режим R (`/plugin-test prefill full`); в тот же день исправлено и проверено вживую
**Приоритет:** 🔴 Блокер релиза — покупатель видит ложное утверждение о своём заказе на самом обычном пути (опечатка в почте)
**Сценарий:** F-36 (браузер, K1) и новый [F-44](../../tests/TEST-PLAN.md), воспроизведено гостем через curl

## Что ожидалось

[RULES.md P10](../../concept/RULES.md): диалог потери выбора показывается, когда выбор **пропал при пересчёте**: «эхо есть, шаг считался, в ответе выбора нет». «Не считался шаг (`fast_render`, короткое замыкание, выключен) — молчим (B2a)». Ошибка в почте или городе не теряет выбор доставки: после исправления ошибки эхо вернёт его (P9).

## Что получилось

Воспроизведение гостем (чистая банка кук, товар 847, количество 1):

1. Здоровый `POST /order/calculate/`: регион Новосибирск, `shipping[type_id]=todoor`, `shipping[variant_id]=33.courier`, адрес с `zip` и `podezd`, валидные имя, телефон и почта, `payment[id]=20`. Пишутся оба эхо-кэша.
2. Тот же запрос, но `auth[data][email]=not-an-email`.

В логе второго запроса:

```
Lost choice check  kind: delivery  lost: true   reason: missing_in_response  echo_id: 33.courier  selected_id: null
Lost choice check  kind: payment   lost: false  reason: step_skipped         echo_id: 20
```

Клиент получает событие `prefill_delivery_lost` и показывает «Нужно выбрать другую доставку. Мы пересчитали заказ, и выбранный вами способ доставки больше не подходит». На экране при этом цела вся доставка: курьер выбран, ничего не пропало.

Карта по видам ошибки (один и тот же здоровый запрос перед каждой строкой, `fp2.php` из этого прогона):

| Ошибка во втором запросе | `error_step_id` | delivery | payment |
|---|---|---|---|
| нет (контроль) | `confirm` | kept | kept |
| битая почта `not-an-email` | `auth` | **lost: true** | step_skipped |
| почта админа (`admin_error`) | `auth` | **lost: true** | step_skipped |
| `test@mail..ru` (ошибка только сервера) | `auth` | **lost: true** | step_skipped |
| пустой город | `region` | **lost: true** | step_skipped |
| не заполнен обязательный `zip` | `confirm` | kept | kept |
| не принят чекбокс согласия | `confirm` | kept | kept |

Браузер, K1 (админ с историей), живьём: развернуть «Покупателя», вписать `test@mail..ru`, «Свернуть». Поверх диалога проверки («Ой! Кажется, не всё готово») в DOM лежит второй открытый диалог «Нужно выбрать другую доставку» (виден, когда закрыть верхний).

## Причина (по коду, подтверждена логом)

`LostChoiceDetector::decide()` получает `step_skipped` из `$state->isStepSkipped('shipping')`, а тот истинен только при `vars.shipping === []` ([shopPrefillCheckoutState.class.php:825](../../../lib/classes/checkout/shopPrefillCheckoutState.class.php#L825)). Ядро кладёт пустой массив лишь тогда, когда `prepare()` шага не успел отрисовать HTML. Но `shopCheckoutStep::prepare()` при уже упавшем шаге выше вызывает `addRenderedHtml()`, и при запрошенном `shipping[html]` результат шага не пуст (содержит `html`). Поэтому после ошибки `auth`/`region` `isStepSkipped('shipping')` ложно, варианта в ответе нет (шаг не считался), и детектор объявляет потерю. Для оплаты случайно работает (`vars.payment === []` в этих запросах), для доставки нет.

Допущение в комментарии к `isStepSkipped()` («упал шаг выше — результат пуст») неверно для шагов, которым запрошен HTML.

## Область поражения

Любой покупатель с выбранной доставкой, у которого шаг авторизации или региона дал ошибку: опечатка в почте, чужая почта, пустой город после правки. Часто и безобидно по ощущению, но диалог говорит неправду («способ доставки больше не подходит») и сбивает с толку. Диалог разовый на выбор, затем отметка сбрасывается при первом `kept`, то есть повторится при следующей ошибке после исправления.

Автотесты это не ловят: `LostChoiceDetectorTest` проверяет таблицы истинности по готовым фактам, а факт «шаг не считался» вычисляется в `CheckoutState` по живому ответу ядра. F-43 (здоровый обход) тоже не поймал, потому что в нём нет ни одной ошибки.

## Направление исправления (для решения владельца)

Первая версия этого раздела предлагала `getBlockingGroupFor('delivery') !== null`. **Это не работает для ошибки региона**: шаг `region` принадлежит группе `delivery` (`STEP_TO_GROUP`), а метод блокирует только группы *строго после* упавшей. Для `auth` сработало бы, для `region` нет.

Рабочий вариант: решать по **положительному признаку того, что ядро посчитало шаг**. Живая проверка 04.10.2026 (гость, `html=1` и `html=only`):

| Состояние | `vars.shipping` | `vars.payment` |
|---|---|---|
| здоровый запрос | `selected_variant_id="33.courier"`, `types`, … | `selected_method_id="20"`, `methods`, … |
| ошибка `auth` | только `html` | только `html` |
| ошибка `region` | только `html` | только `html` |
| тип без варианта (шаг доставки посчитан, выбора нет) | `selected_variant_id=null` (ключ **есть**), … | только `html` |
| то же при `html=only` | `types` вырезан, `selected_variant_id` остался | `methods` вырезан, `selected_method_id` остался |

Значит `array_key_exists('selected_variant_id', vars.shipping)` отличает «посчитан, выбора нет» (настоящая потеря) от «не считался» (ошибка выше, `fast_render`, шаг выключен). Подробный разбор вариантов — в обсуждении от 04.10.2026; новый метод `CheckoutState` должен называться отдельно от `isStepSkipped()`: тот отвечает на вопрос «рисовало ли ядро секцию» и нужен Дзен-карточкам.

## Что сделано

`CheckoutState::wasStepProcessed()` ([shopPrefillCheckoutState.class.php](../../../lib/classes/checkout/shopPrefillCheckoutState.class.php)): шаг считается посчитанным, только если в `vars.<шаг>` есть ключ, который кладёт `process()` (`selected_variant_id` у доставки, `selected_method_id` у оплаты). Хук подтверждения решает по `isFastRender() || !wasStepProcessed('shipping')`. `isStepSkipped()` не тронут: он отвечает на другой вопрос («рисовало ли ядро секцию») и нужен Дзен-карточкам.

Проверено:

- автотест `tests/CheckoutStateStepProcessedTest.php`: 34 проверки, фикстуры сняты с живого ответа ядра в режимах `html=1` и `html=only`; 4 мутанта убиты (хук вернулся к `isStepSkipped`; признак `types`; признак «непустой массив»; убран признак доставки);
- карта ошибок гостем (`docs/tests/scripts/f44-upstream-error-map.php`): `auth` ×3 и `region` дают `delivery: step_skipped`, контроль и `details`/`confirm` — `kept`;
- положительный контроль: при 3 шт. выбрана бандероль, при 6 шт. её нет в списке — `delivery lost: true (missing_in_response)`, повтор того же запроса — `already_notified`;
- браузер, K1: `test@mail..ru` + «Свернуть» — один диалог проверки формы, ложного «Нужно выбрать другую доставку» нет; лог `delivery step_skipped`.
