# Настройки плагина не рендерятся на классическом бэкенде (UI 1.3): `$switcher.waSwitch is not a function`

**Статус:** не баг — плагин поддерживает только дизайн-систему Webasyst 2.0, классический UI 1.3
не заявлен как поддерживаемый. На Docker-стенде включена 2.0 (тумблер «Turn on the new UI»),
после этого `wa.js`/`waSwitch` доступны и настройки открываются штатно. Оставляю файл как запись
наблюдения — если понадобится явно задокументировать это ограничение в `requirements.php` или
README, разбор ниже пригодится.

## Наблюдение

Обнаружено 30.08.2026 сразу после починки [smarty-quote-break-old-webasyst.md](smarty-quote-break-old-webasyst.md),
на том же Docker-стенде (`webasyst-framework v2.9.0` / `shop-script v10.0.0`, ~/Project/shop10-docker).
После фикса апострофа страница настроек плагина открывается, но содержимое вкладок (General/Zen
Mode/Design/Debug) не рендерится — пустая область под ссылками вкладок. В консоли:

```
TypeError: $switcher.waSwitch is not a function
    at PrefillSettings.switcher (prefill.settings.js:19/34/202)
    at initPrefillSettings (prefill.settings.js:1156)
```

Причина: `$.fn.waSwitch` определяется в `wa-content/js/jquery-wa/wa.js`, но на этой инсталляции
на странице плагинов загружен только `wa.header-legacy.js` — `wa.js` не подключён вовсе. Плагин
нигде сам не подключает `wa.js` (grep по `templates/actions/settings/blocks/Head.html` и
`shopPrefillPluginSettings.action.php` — ни одного упоминания `wa.js`/`waSwitch`), а полагается
на то, что бэкенд-раскладка подключает его глобально — что верно только для интерфейса
Webasyst 2.0 (баннер "Turn on the new UI" на этой инсталляции показывает, что сейчас активен
классический UI 1.3, где `wa.js`, судя по всему, не подтягивается на эту страницу).

Перекликается с уже отмеченным в `TODO.md` пробелом: "легаси UI 1.3" числился непроверенным
для фикса подсветки «Мои варианты» — теперь есть конкретный, воспроизводимый разрыв на этом же
UI ещё до того экрана, прямо на самих настройках плагина.

## Не разобрано

- Ломается ли на UI 1.3 только сама страница настроек (эта JS-инициализация) или витрина/чекаут
  тоже используют `waSwitch`/`wa.js` где-то ещё.
- Правильный фикс: подключать `wa.js` явно в `Head.html` плагина (независимо от активной темы
  бэкенда), или переписать переключатель без зависимости от `waSwitch`. Не выбирался.
- Не проверено на текущей рабочей инсталляции (12.6.0) — там, видимо, `wa.js` подключается
  бэкенд-раскладкой глобально по умолчанию, но не подтверждено вживую.
