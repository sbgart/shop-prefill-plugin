# Кнопка «Свернуть» на пустой секции `auth`: клик гоняет recalculate вхолостую, без единого сообщения

**Статус:** исправлено 06.09.2026, проверено в браузере и curl-ом.

## Воспроизведение (06.09.2026)

Чистый гость, curl с пустой банкой кук (без переиспользования браузерных кук — см. приём в
[CLAUDE.md](../../../../../CLAUDE.md#авторизация)):

```bash
J=guest.jar; rm -f $J
curl -sk -c $J -b $J https://wa-dev.loc/ -o /dev/null
curl -sk -c $J -b $J -X POST https://wa-dev.loc/cart/add/ -d 'product_id=934&sku_id=2322&quantity=1'
curl -sk -c $J -b $J https://wa-dev.loc/order/ -o order1.html
```

В ответе все три группы (`customer`, `delivery`, `payment`) отрендерены **развёрнутыми** —
`data-action="collapse"` на кнопке, то есть кнопка «Свернуть» показана, хотя ни одно поле нигде не
заполнено. Лог (`wa-log/prefill.plugin.log`) на этот же запрос:

```text
[DEBUG] Zen group 'customer' expanded: nothing to summarize yet
[DEBUG] Zen group 'delivery' expanded: nothing to summarize yet
[DEBUG] Zen group 'payment' expanded: nothing to summarize yet
```

Секция `auth` в HTML не несёт ни одного `required`-атрибута ни на одном поле:

```html
<input name="auth[data][firstname]" type="text" value="">
<input name="auth[data][lastname]" type="text" value="">
<input name="auth[data][phone]" type="tel" value="" placeholder="+X 111 222-33-44">
<input name="auth[data][email]" type="email" value="">
```

— у этой витрины гостевой заказ разрешён без единого обязательного контактного поля
(`order_without_auth`).

## Механизм

Две независимые проверки «можно ли свернуть», и клиент знает только про одну:

1. **Клиент** (`js/modules/ZenModeToggle.js:230` `validateSections()`) вызывает
   `form.sections['auth'].getData({render_errors:true})` и смотрит на `sectionData.errors` —
   это **исключительно** валидация обязательных полей ядра (`required`, формат email/телефона
   и т.п.).
2. **Сервер** (`shopPrefillPluginZenMode::shouldCollapseGroup()`,
   `lib/classes/zenmode/shopPrefillPluginZenMode.class.php:196`) сворачивает группу только если
   `isGroupMinimumFilled()` (`shopPrefillPluginSectionChecker.class.php:237`) видит хотя бы одно из
   `data.email` / `data.phone` / `data.firstname` в параметрах сессии — правило Z2
   ([RULES.md:70](../concept/RULES.md)): «не сворачиваем то, где нет данных».

На витрине без обязательных полей auth эти две проверки расходятся: клиентская валидация всегда
проходит (ошибок формата/обязательности нет — полям просто нечего проверять), а серверная
всегда отказывает (данных для сводки нет). Последовательность по клику
(`ZenModeToggle.collapseGroup()`, строки 112–152):

1. `hasErrors = validateSections(...)` → `false` (нет обязательных полей → нет ошибок).
2. Плагин снимает cookie `prefill_zen_customer` (её и не было) и вызывает `form.update()` —
   это полноценный AJAX `calculate` по всем секциям чекаута, воспринимается покупателем как
   перезагрузка.
3. Сервер на этом же recalculate независимо проверяет `shouldCollapseGroup('customer', ...)`:
   кука не `expanded`, ошибок нет, но `isGroupMinimumFilled` снова `false` — группа рендерится
   развёрнутой, **тем же HTML, что и был**.

Итог: покупатель видит клик → сетевой запрос → тот же самый развёрнутый блок, без единого
сообщения, что́ произошло и почему ничего не свернулось. С точки зрения `ZenModeToggle` действие
завершилось успешно (`this.logger.info("User collapsed the customer group section")` даже
пишется в лог!) — при том, что по факту ничего не свернулось.

Само по себе несворачивание — не баг, это Z2/Z4 в чистом виде (RULES.md:70,76): группа с пустыми
данными обязана остаться развёрнутой, и это залипает на всю сессию (Z4), пока покупатель
действительно что-то не введёт. Баг — в том, что кнопка «Свернуть» **безусловно** выводится в
развёрнутом состоянии (`templates/zenmode/ToggleButton.html:20-28`, ветка `else`, без всякой
проверки на «а есть ли вообще что сворачивать»), и клик по ней ничего не сообщает пользователю,
хотя сервер прекрасно знает заранее (`isGroupMinimumFilled()`), что сворачивание невозможно.

Не путать с [zen-customer-group-never-collapses-f01.md](zen-customer-group-never-collapses-f01.md):
там речь о **заполненных** данных авторизованного покупателя, которые не сворачиваются из-за гонки
прогрева сессии на первом кадре + кука-защёлка. Здесь данных нет вообще, поведение сервера
корректное и ожидаемое — не так у клиента, который не различает «нечего сворачивать» и «есть
ошибка».

## Решение (06.09.2026)

Сервер помечает кнопку «Свернуть» атрибутом `data-nothing-to-summarize="1"`, когда минимума
данных нет, а JS после пересчёта показывает по нему отдельный диалог
(`zen.nothing_to_summarize.*`). Само поведение сервера не менялось: группа с пустыми данными
по-прежнему остаётся развёрнутой (Z2), защёлка Z4 не тронута.

Правки: `shopPrefillPluginZenMode::renderCollapseBlock()`, `templates/zenmode/ToggleButton.html`
и `CollapseBlock.html`, `js/modules/ZenModeToggle.js`, `shopPrefillPluginFrontendHooks` +
локали ru/en.

Две ошибки, которые всплыли при реализации и стоят отдельного упоминания:

1. **Признак нельзя брать из `getLastDecision()['reason']`.** Причина отвечает на вопрос «почему
   группа развёрнута *сейчас*», а со второго запроса сессии это всегда кука-ветка
   (`expanded_by_user`), которая короткозамыкает `shouldCollapseGroup()` до проверки данных.
   Первая реализация так и делала — признак жил ровно один кадр и молча пропадал. Спрашивать
   надо данные напрямую: `!$is_collapsed && !isGroupMinimumFilled($group)`.
2. **Клиент обязан читать признак после `form.update()`, а не до клика.** Разметку рендерит
   сервер, и покупатель может заполнить поле уже после последнего рендера — тогда атрибут
   устарел, сворачивание законно, а предупреждение до клика было бы враньём (и регрессом:
   старый код в этом сценарии сворачивал верно). `form.update()` возвращает thenable, поэтому
   проверка вешается на его завершение, когда сервер уже видел свежие данные.

Проверено: чистый гость curl-ом (атрибут на всех трёх группах, держится и на втором кадре, когда
защёлка уже стоит; после отправки данных — исчезает) и в браузере — при заполненных данных группа
сворачивается со сводкой и без диалога, при пустых остаётся развёрнутой и показывает диалог.
14 автотестов плагина зелёные.

⚠️ Прод-бандл `prefill.frontend.min.js` намеренно не пересобирался — это делает `/release-pack`.

## Отвергнутые варианты

- **Прятать кнопку «Свернуть», когда сворачивать нечего.** Проверено и отвергнуто: при защёлке Z4
  клик по этой кнопке — **единственный** способ, которым покупатель за сессию вообще получает
  свёрнутый блок. Замер: в свежей гостевой сессии заполнены имя, фамилия, телефон и email — группа
  всё равно вернулась развёрнутой (`data-action="collapse"`), потому что кука `expanded`,
  выставленная на первом кадре, короткозамыкает проверку данных. Убрать кнопку — сделать
  дзен-режим для гостя недостижимым.
- **Не писать защёлку при `minimum_not_filled`** (первоначально предлагалось как «общий корень» с
  [f01](zen-customer-group-never-collapses-f01.md)). Отвергнуто: у f01 корень другой — гонка на
  первом кадре, когда `isGroupMinimumFilled()` читает ещё не прогретые параметры сессии, хотя поля
  формы уже предзаполнены. Защёлка там лишь продлевает единичный промах, а не создаёт его, и её
  снятие f01 не чинит — группа просто сворачивалась бы позже и не вовремя. Плюс это прямо ломает
  Z4: минимум группы `customer` срабатывает по любому из имени/телефона/email, то есть блок
  схлопывался бы сразу после первого введённого поля, посреди ввода.

## Не разбиралось

- Воспроизводится ли то же самое для `delivery`/`payment`, если у витрины способ доставки/оплаты
  можно оставить невыбранным без ошибки core (на этой витрине оба шага требуют выбора варианта, то
  есть `hasErrors` там скорее всего не будет `false` — не проверено вживую). Фикс их покрывает:
  атрибут ставится всем трём группам.
- Поведение на витрине, где `order_without_auth` запрещает пустой auth: там есть обязательные поля,
  и до нового диалога дело не доходит — срабатывает штатный `showValidationErrorDialog()`.
  На этом стенде с переключённой настройкой не проверялось.
