# Глобальная настройка `zen.icon_display`: «По умолчанию» и «Логотипы плагинов» неотличимы (F-19)

**Статус:** исправлено 06.09.2026 — см. «Решение» в конце файла. Обнаружено 05.09.2026 при подготовке F-19 (прогон R, ФО-06).

## Воспроизведение

1. Настройки плагина → вкладка «Дзен-режим» → «Иконки в свёрнутых блоках» (`zen.icon_display`,
   `storefront_code='*'`, id=76) — три опции: «Логотипы способов доставки и оплаты» (`plugin`),
   «Стандартные иконки блоков» (`default`), «Без иконок» (`none`); подсказка ничего не говорит
   про то, что опция работает только вместе с другой настройкой.
2. На вкладках «Доставка»/«Оплата» есть отдельная настройка «Иконка блока «Доставка»» / «...«Оплата»»
   (`icon_source`, per-group) с опциями «По умолчанию» / «Логотипы плагинов» / «Своя иконка».
3. Выставить `zen.icon_display = default` (глобально), но `zen.groups.delivery.icon_source = plugin`
   (или наоборот).

**Ожидание (по тексту UI):** глобальный переключатель — это выбор режима иконок для всех блоков
сразу; «По умолчанию» должен показывать стандартные SVG-иконки везде, «Логотипы плагинов» —
логотипы способов доставки/оплаты везде.

**Факт (по коду):** значение `icon_display` читается только в двух местах —
`shopPrefillPluginZenMode::getIconDisplayMode()` и `shopPrefillPluginFrontendHooks::initializeFrontendAssets()`
(строка ~232) — и в обоих случаях сравнивается **только** с `'none'`
(`$icon_mode !== 'none'` / `... !== 'none'`). Различие между значениями `'default'` и `'plugin'`
нигде в кодовой базе не проверяется (проверено полным `grep -rn "icon_display"` по `lib/` и `js/` —
только три вхождения: определение дефолта в `storefront.settings.php` и эти два условия).

Реальный тип иконки для delivery/payment выбирает **отдельная** per-group настройка `icon_source`
(`shopPrefillPluginZenMode::getPluginGroupIcon()`, строка 300-316) — независимо от значения
глобального `icon_display`. Для customer — своя `icon_source` (`default`/`none`/`custom`/`avatar`,
`getCustomerGroupIcon()`, строка 326-340), тоже без оглядки на `icon_display`.

Итого: `icon_display = 'default'` и `icon_display = 'plugin'` **всегда** ведут себя одинаково —
единственный работающий переход глобальной настройки — это включение/выключение иконок целиком
(`'none'` против любого другого значения). Реальный выбор типа иконки происходит только через
per-group `icon_source`, которую нужно менять на каждой из трёх вкладок отдельно.

## Не разбиралось (актуально до фикса)

- Было ли задумано, что `icon_display` — это только «показать/не показать», а два «активных» текста
  опций («Логотипы...» / «Стандартные...») — ошибка формулировки хинта/лейблов, либо `icon_display`
  должен был на самом деле проставлять дефолт для всех трёх `icon_source` разом (и это не реализовано).
- Поведение при полностью дефолтных `icon_source` на всех трёх группах (`'default'` везде) —
  тогда внешне `icon_display=plugin` и `icon_display=default` неотличимы вдвойне, случай не
  проверялся отдельно.

## Решение (06.09.2026)

Вместо починки различения `default`/`plugin` глобальная настройка `zen.icon_display` убрана целиком
(вкладка «Дзен-режим» → «Основные настройки») — вместе с ней исчез сам вопрос «что главнее, глобальный
режим или per-group `icon_source`». Вместо неё в per-group `icon_source` для delivery и payment
добавлена опция `none` («Без иконки»), уже существовавшая только у customer
(`default`/`none`/`custom`/`avatar`) — теперь у всех трёх групп единый паттерн, каждая самодостаточна.

Правки:
- `lib/config/storefront.settings.php` — ключ `zen.icon_display` удалён; `groups.delivery.icon_source`
  и `groups.payment.icon_source` теперь допускают `none` (дефолт по-прежнему `'default'`).
- `templates/actions/settings/blocks/tabs/Zen.html` — убрано поле-селект `icon_display`; в селекты
  delivery/payment добавлена опция `none` (лейбл `zen.icon_source.none` уже существовал — переиспользован
  как есть, отдельного ключа для delivery/payment заводить не пришлось).
- `lib/classes/zenmode/shopPrefillPluginZenMode.class.php` — удалены мёртвые `getIconDisplayMode()` и
  `shouldShowIcons()`; `getPluginGroupIcon()` получил `case 'none'` (тот же паттерн, что уже был в
  `getCustomerGroupIcon()`); `renderCollapseBlock()` больше не оборачивает расчёт иконки во внешний
  гейт «глобальный режим не none» — видимость и тип иконки теперь решает исключительно per-group
  `icon_source`, единообразно для всех трёх групп.
- `lib/classes/hooks/shopPrefillPluginFrontendHooks.class.php` — CSS-переменные размера иконки
  (`prefill-zen-icon-width/height`) больше не зависят от удалённого `icon_display`, только от
  `zen.active`; неиспользуемая переменная при `icon_source=none` во всех группах безвредна.
- Локали (ru_RU, en_US): убраны `zen.icon_display*` (5 ключей); хинты `hint.zen.icon_source.delivery`
  и `.payment` дополнены упоминанием «без иконки»; `zen.icon_size` переименован в «Размер иконок в
  свёрнутых блоках» (был просто «Размер иконок» — терял смысл после исчезновения соседней настройки).

Проверено: 18 автотестов зелёные (в т.ч. `ZenGroupCarrierTest`, которого правки не касаются), вживую в
браузере — `icon_source=none` для payment даёт свёрнутый блок без иконки (`Zen.html` → сохранение →
`/order/` → ручное сворачивание группы «Оплата» через кнопку «Свернуть» → иконки нет, сводка и кнопка
«Изменить» на месте). Значение payment вернул к исходному (`plugin`) после проверки.

Миграция для существующих инсталляций не делалась: плагин ещё не продавался (TODO.md — «важно до
продажи»), живых значений `icon_display` в БД нет.
