# `zen.active = false` не отключает Zen-режим (F-16)

**Статус:** факт, не разобран.

## Воспроизведение (28.08.2026, прогон R, ФО-06, сценарий F-16, конфигурация K9)

1. В `shop_prefill_settings` добавлена строка `storefront_code='d2EtZGV2LmxvYy8q'` (`wa-dev.loc/*`),
   `name='active'`, `groups='["zen"]'`, `value='0'` — до этого override для `zen.active` на этой
   витрине не было, использовалось значение по умолчанию (`true`) из `storefront.settings.php`.
   Формат строки идентичен другим рабочим override-строкам `zen.active` в этой же таблице
   (например `id=41`, `groups=["zen"]`, для витрины `wa-dev.loc/shop/*`).
2. Свежая сессия (новый cookie jar, логин `admin`/`123`), товар в корзине, `GET /order/`.

**Ожидание (F-16, [TEST-PLAN.md](../tests/TEST-PLAN.md)):** ни одна группа не свёрнута,
`zenmode.css` не подключается.

**Факт:** группы `delivery` и `payment` по-прежнему рендерятся свёрнутыми
(`data-action="expand"`, есть кнопка «Изменить», сводка показана), `zenmode.css` по-прежнему
подключён (`<link>` в разметке). Поведение полностью совпадает с состоянием при
`zen.active` по умолчанию (`true`) — настройка `active=0` группы `zen` видимого эффекта не имеет.

Воспроизведено дважды подряд (два последовательных `GET /order/` в одной сессии) — не гонка загрузки.

## Не разбиралось

Читает ли `shouldCollapseGroup()` / выбор ассетов вообще leaf `zen.active`, или он подмешивается
в effective-settings иначе, чем остальные `zen.groups.*.enabled` (последние, судя по прежним
находкам этого прогона, применяются штатно — см. F-17 в TEST-PLAN.md, не проверялось отдельно
в этом прогоне).

## Уборка

Тестовая строка `id=326` удалена сразу после проверки — override для этой витрины снова отсутствует
(значение вернулось к дефолту `true` из кода, ничего восстанавливать не нужно).
