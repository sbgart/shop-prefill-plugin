# Баг: кастомные поля оплаты теряются при смене доставки

**Статус:** Не решаемо на уровне PHP без JS-перехвата  
**Компонент:** `shopPrefillPluginSessionStorageProvider`, механизм `prefill_snapshot`

---

## Описание

Если пользователь:
1. Выбрал способ оплаты Y → AJAX → snapshot сохранил `payment.id = Y` ✅
2. Заполнил кастомные поля оплаты (ИНН, название компании и т.д.) — **AJAX не отправился**
3. Сменил способ доставки → AJAX → Shop-Script очищает секцию `payment`

**Результат:** `payment.id = Y` восстанавливается из snapshot, но кастомные поля (`payment.custom.*`) теряются — они никогда не попали в сессию, т.к. не было AJAX-запроса между шагами 2 и 3.

## Причина

Кастомные поля оплаты попадают в `shop/checkout` только в момент AJAX-запроса (когда браузер отправляет form data). Если после заполнения кастомных полей пользователь сразу переключает доставку — эти значения существуют только в DOM браузера.

Snapshot сохраняет только то, что уже прошло через сессию. Перехватить «незакоммиченные» данные DOM на PHP-уровне невозможно.

## Частичное смягчение

Если пользователь уже оформлял заказ с теми же кастомными полями — они будут восстановлены из `fill_params` (данные последнего заказа). Это покрывает большинство реальных случаев (повторные покупки).

## Теоретическое решение

Перехватить отправку AJAX-запроса на JS-стороне, добавить в него текущие значения кастомных полей до смены доставки. Реализация нетривиальна и создаёт риски нарушить другие части процесса оформления заказа.

**Вывод:** допустимый компромисс, не стоит затрат на реализацию.
