# `$delivery_photos_html` и `$delivery_schedule` — вёрстка ядра не работает в Zen-карточке

**Статус:** исправлено 08.09.2026 — оба поля переведены на собственные классы и собственный CSS,
проверено вживую на тёмной теме. Разбор ниже сохранён: он объясняет, почему нельзя было
ограничиться дописыванием недостающего класса-предка.

## Наблюдение

29.08.2026, живой чекаут, способ доставки «Пункт выдачи заказов» (`sd`, `id=37`) с 2 реальными
загруженными фото. Кастомный Zen-шаблон группы `delivery` вставляет `{$delivery_photos_html}` как есть.

Свёрнутая карточка получает корректный HTML (проверено через `innerHTML`) — та же самая разметка,
что и у ядра: `<div class="wa-line wa-photos-section" data-name="…">`, `.wa-action.left/right` со
стрелками, `.wa-photos-list > .wa-photo-wrapper × 2` с правильными `data-image-uri`. Структурно всё
на месте. Но **визуально фотографий нет вообще** — видны только две несвязанные "голые" стрелки одна
под другой, без единой картинки.

Проверено через `getComputedStyle()`/`getBoundingClientRect()` на живом `.wa-photo-wrapper` внутри
`.prefill-zen-summary`:

| Свойство | Ожидается (правило ядра) | Фактически в Zen-карточке |
|---|---|---|
| `display` | `inline-block` | `block` |
| `width` | `calc(25% - 15px)` | `489px` (100% контейнера) |
| `position` | `relative` | `static` |
| `padding-bottom` | `calc(25% * 0.75 - 15px)` (аспект-рейшо) | `0px` |
| `getBoundingClientRect()` | ненулевая высота | **489 × 0px — нулевая высота** |

`.wa-action.left` (стрелка) — ожидается `position: absolute; top: 0; height: 100%; width: ~27px`,
фактически `position: static; width: 489px` (растянута на всю ширину, поэтому стрелки садятся друг
под другом вместо боков галереи). `.wa-photos-section` — ожидается `position: relative; white-space: nowrap`,
фактически `position: static; white-space: normal`.

## Причина

Ядро (`wa-apps/shop/css/frontend/order/form.css`) стилизует галерею строго через явный
предок-селектор:

```css
.wa-order-form-wrapper .wa-step-details-section .wa-details-rates-section
  .wa-photos-section .wa-photos-list .wa-photo-wrapper { width: calc(25% - 15px); ... }
```

Zen-карточка (`templates/zenmode/CollapseBlock.html`) — плоская разметка
`.prefill-zen-collapse-block > .prefill-zen-content > .prefill-zen-summary`, без единого из требуемых
предков (`.wa-step-details-section`, `.wa-details-rates-section`). Правило ядра физически не может
совпасть ни с одним селектором внутри карточки — плагин переиспользует классы ядра, рассчитывая на
его CSS/JS (лайтбокс, скролл, `Details.prototype.initPhotos()`), но эти классы вне их родного дерева
не значат ничего.

### Уточнение 08.09.2026 (после починки источника расписания)

Три поправки к разбору выше — каждая меняет оценку возможных решений.

1. **Один предок из двух на месте.** Карточка группы `delivery` вставляется хуком
   `checkout_render_details`, а он в ядре стоит внутри `<section class="wa-step-details-section">`
   (`details.html:339`). Не хватает ровно одного класса — `.wa-details-rates-section`, у которого
   собственных правил всего одно (`margin-top: 1.07em`).
2. **У расписания дыра глубже и другой природы.** Замеры на живом СДЭК ПВЗ: `.wa-day-wrapper`
   получает `display: block` вместо `table`, день занимает 42px в две строки вместо 17px в строку,
   `.wa-date` — `block` на всю ширину вместо `table-cell` 185px. Причина не только во внешнем
   предке: `renderPickupSchedule()` отдавал голые `.wa-day-wrapper`, без обёрток
   `.wa-schedule-wrapper > .wa-days-wrapper`, которых требуют селекторы ядра (`details.html:236-245`).
   То есть дописывание одного класса-предка расписание бы не починило.
3. **JS ядра не «не вызывается» — он вызывается и ломается.** `Details.prototype.initPhotos()`
   ищет `.wa-photos-section` по всей секции details (`form.js:2091-2093`), а скрытая ядровая
   галерея из DOM никуда не девается: CSS сворачивания прячет её через
   `form > *:not(.wa-plugin-hook){display:none}`. Слайдер получал коллекцию из двух секций и
   считал ширину по `outerWidth()` первой — невидимой, то есть по нулю (`form.js:2270-2277`).
   Плюс `data-name` для заголовка лайтбокса брался тоже у скрытой ядровой.

## Воспроизведение

1. Настроить ПВЗ-способ доставки (`sd`/`regionalpickup`/`sydsek`) минимум с одним загруженным фото.
2. В Zen-редакторе шаблонов вставить `{$delivery_photos_html}` в шаблон группы `delivery`.
3. Оформить заказ этим способом, свернуть карточку доставки.
4. DevTools → `.prefill-zen-summary .wa-photo-wrapper` → Computed: `width` растянут на всю карточку,
   `padding-bottom: 0`, итоговая высота элемента — 0px.


## Решение

Обе разметки переписаны на собственные классы плагина, вид задаёт `css/zenmode.css`:

| Было (классы ядра) | Стало |
|---|---|
| `.wa-line.wa-photos-section` + `.wa-action.left/right` + `.wa-photos-list` + `.wa-photo-wrapper` + `.wa-photo.js-show-photo` (фон картинкой) | `.prefill-zen-photos` (flex-ряд с горизонтальной прокруткой) + `.prefill-zen-photo` (`<a>` с `<img loading="lazy">`) |
| `.wa-day-wrapper` + `.wa-date` + `.wa-value` + `.wa-time` + `.wa-text` + `.wa-additional` | `.prefill-zen-schedule` (grid в две колонки) + `-date` / `-hours` / `-time` / `-off` / `-note` |

Почему свои классы, а не дописать `.wa-details-rates-section` в карточку:

- **Совпадение имён — это не наследование дизайна, а попадание под чужие правила.** Тема витрины
  правит чекаут именно по неймингу ядра (в `default` — 22 правила на `.wa-order-form-wrapper`,
  с `!important` и своими переменными), и в ней уже есть правило на `.wa-date` — класс, который
  расписание генерировало само. Сейчас спасал только скоуп темы на `.wa-step-shipping-section`.
- **CSS ядра для этих узлов не темовый, а приложенческий**, с захардкоженными `#333`/`#888`/`#aaa` —
  на тёмной теме он не подстраивается. Проверено: ни одного правила на `.wa-photo-wrapper`,
  `.wa-day-wrapper`, `.wa-photos-section`, `.wa-details-rates-section` в теме нет.
- **Адаптация к теме приходит по наследованию, а не по имени класса.** Карточка и так внутри
  `.wa-order-form-wrapper`, которому тема ставит `font-size: .875em`. Поэтому в своём CSS всё в
  `em`, цвет — `currentColor` с `opacity` (тем же приёмом, каким приглушает `.wa-date` сама тема),
  подложка миниатюры — нейтральный `rgba(127,127,127,.15)`. Ни одного абсолютного цвета.
- **Лайтбокс ядра переиспользовать было нельзя** по причине 3 выше, поэтому и незачем держаться за
  его классы. Клик по фото открывает оригинал в новой вкладке штатной ссылкой — без единой строки JS.
- Метрика ядра при этом сохранена: пропорция 4:3, `border-radius: 3px`, две колонки у расписания.
- Заодно догнали ядро по весу картинок: плагины доставки кладут в `photos` только `uri` оригинала,
  поэтому в карточку 77×58 уезжал полноразмерный файл. `buildThumbUri()` зовёт тот же
  `$wa->shop->imgUrl($uri, '100x75')`, что и `details.html`; внешние ссылки со схемой хелпер
  возвращает как есть, любая его ошибка откатывается на оригинал.

Дополнительно `css/zenmode.css` подключён в бэкенде (`templates/actions/settings/blocks/Head.html`):
раньше превью шаблона в редакторе по построению не могло совпасть с витриной — вид там задавал CSS
ядра из чужого DOM-контекста, которого в админке нет. Теперь превью и витрина берут стили из одного
файла. Заодно `getSampleData()` отдаёт видимый плейсхолдер миниатюры (инлайновый SVG) вместо `uri = '#'`.
