# Дебаг-панель: хардкод русского текста в JS (alert/confirm/innerHTML)

**Статус:** исправлено 05.09.2026.

## Наблюдение (05.09.2026, прогон R, ФО-13, M-03)

Статический grep `js/` на кириллицу вне `_wp()`/`$_()` нашёл 14 срабатываний, все в
`js/prefill.debug.js` (кроме одного уже известного — `logger.debug` в `ParamsChoiceManager.js`,
не пользовательский текст, зафиксировано ещё в L0.4 самого первого прохода этого прогона).

Все 14 — русский текст напрямую в `confirm()`/`alert()`/`innerHTML` дебаг-панели: «Очистить сессию
shop/checkout?», «✅ Хранилище очищено!», «Переключить статус Zen Mode?», «⏳ Обновление...» (это ещё
и `innerHTML = '<div ...>...</div>'` — нарушает отдельное правило проекта «не собирать HTML в JS»)
и т.д. — полный список строк в выводе grep, здесь не дублируется.

Проверка актуального gate уточнила исходное предположение: панель доступна на checkout при глобальном
debug Webasyst и включённой настройке `debug_panel`, в том числе гостю. Только изменяющие команды
ограничены правами администратора Shop-Script; гостю их кнопки не выводятся, а endpoints проверяют
права на сервере.

## Исправление

- Все видимые строки панели перенесены в домен локализации `shop_prefill` для ru_RU/en_US.
- В `js/prefill.debug.js` больше нет кириллицы, успешных `alert()` и HTML через `innerHTML`.
- Сервер отдаёт готовые локализованные Smarty-фрагменты; JS использует клонирование шаблонов,
  DOM API и `textContent`.
- Русский интерфейс проверен в реальном Chrome. PO-файлы обеих локалей скомпилированы штатной
  командой Webasyst; en_US отдельно в браузере не переключалась.
