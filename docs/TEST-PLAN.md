# План тестирования плагина Prefill

**Назначение.** Единый регламент проверки всего функционала перед выпуском версии. Живёт от релиза к релизу: сценарии не переписываются под задачу, а прогоняются заново и отмечаются датой.

**Отношение к соседним документам.**

| Документ | Роль |
|---|---|
| [concept/RULES.md](concept/RULES.md) | Инварианты. Каждый сценарий здесь ссылается на правило, которое он защищает |
| **TEST-PLAN.md** (этот файл) | **Что проверять и в каком объёме.** Реестр областей, сценарии, критерии выпуска |
| [TESTS.md](TESTS.md) | **Что уже проверено.** Журнал прогонов с датами, находками и грабли конкретных проверок |
| [plans/issue-63-browser-test-runbook.md](plans/issue-63-browser-test-runbook.md) | Инструментарий стенда (счётчик SQL, чистая сессия, EXPLAIN). ⚠️ Рецепт с `/prefill/reset-snapshot` устарел — эндпоинта нет с момента снятия снапшота |

Правило ведения то же, что в TESTS.md: **проверка без правила из RULES.md — повод либо добавить правило, либо выкинуть проверку.**

## 1. Объём прогона

Три режима. Выбор — по типу изменения, а не по настроению.

| Режим | Когда | Что входит | Ориентир по времени |
|---|---|---|---|
| **S — смоук** | После любой правки кода, перед коммитом | Уровни L0–L2 целиком + браузерный блок `SMOKE` (§6) | 20–30 мин |
| **T — точечный** | Правка внутри одной области | S + все сценарии затронутой ФО + её соседи по колонке «Задевает» | 1–2 ч |
| **R — релизный** | Перед публикацией версии в магазин | Весь документ, включая §7 (установка/обновление) и §8 (совместимость) | 1–2 дня |

Для 1.0.0 обязателен **R**: областей, ни разу не проверенных целиком в текущей редакции кода, ещё много (см. колонку «Покрытие» в §3).

## 2. Уровни тестирования

### L0 — статика (без запуска, автоматизируемо)

```bash
cd wa-apps/shop/plugins/prefill

# 1. Синтаксис PHP 7.4 на всех файлах плагина
find lib -name '*.php' -exec php -l {} \; | grep -v 'No syntax errors' || echo "L0.1 OK"

# 2. Нет синтаксиса PHP 8+ (именованные аргументы, union types, enum, readonly)
grep -rnE '\b(enum|readonly)\s|\)\s*:\s*[A-Za-z]+\|' lib/ && echo "L0.2 ПРОВЕРИТЬ" || echo "L0.2 OK"

# 3. Ядро не тронуто — правок вне каталога плагина нет (B1)
git -C ../../../.. status --porcelain -- wa-system wa-apps/shop --

# 4. Хардкод русского текста в пользовательской поверхности.
# Исключены: min-бандл, комментарии и отладочная поверхность (js/prefill.debug.js,
# templates/debug/) — она видна только админу при глобальном debug.
grep -rnP '["\x27][^"\x27]*[а-яА-Я]{3}' js/ templates/ \
  --include='*.js' --include='*.html' --exclude='*.min.js' \
  --exclude='prefill.debug.js' --exclude-dir='debug' \
  | grep -v '_wp' | grep -vP ':\s*(//|\*|\{\*)'

# 5. Каждый роут плагина оканчивается на /? (иначе адрес со слэшем даёт 404)
test "$(grep -c "=> 'frontend/" lib/config/routing.php)" \
   = "$(grep "=> 'frontend/" lib/config/routing.php | grep -c "/?'")" && echo "L0.5 OK"

# 6. Сборка архива проходит валидацию ядра (синтаксис, конфиг, структура БД)
php ../../../../wa.php compress shop/plugins/prefill -style false
```

## 10. Критерии выпуска

Версия не публикуется, пока не выполнено **всё**:

1. **L0–L2 зелёные** — статика, все автотесты, все curl-проверки.
2. **Все 🔴-области (ФО-01…04, 06, 07, 11, 14) прогнаны целиком** на текущей сборке, а не по памяти прошлых прогонов.
3. **Ни одного открытого 🔴 и 🟠 в [TODO.md](TODO.md)** — либо закрыт, либо сознательно отложен с записью причины (как issue-79).
4. **`SMOKE`-набор прогнан на конфигурациях K1, K2, K7, K9, K14** — минимум, доказывающий что выключенный плагин, выключенный дзен и гость не ломают чекаут.
5. **L5 полностью** — сборка, чистая установка, обновление с предыдущей версии, удаление.
6. **S-01 определена** — минимальная поддерживаемая версия записана в `requirements.php`, а не угадывается.
7. **Логи чисты** — ни одного `error` плагина, PHP-лог без новых записей.
8. **Отчёт о прогоне сохранён** в `docs/releases/`, статусы в [TESTS.md](TESTS.md) обновлены датой.

Пункты 1, 2, 5 и 7 — блокирующие безусловно. Остальные могут быть сняты явным решением с записью в отчёте.
