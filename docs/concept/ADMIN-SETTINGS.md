## Настройки витрины в админке (спека по реализации)

Источник истины по дефолтам: `lib/config/storefront.settings.php`.

UI сейчас состоит из вкладок:

- `General` — основная вкладка (витрина и предзаполнение): `templates/actions/settings/blocks/tabs/General.html`, `templates/actions/settings/blocks/tabs/Prefill.html`
- `Design` (`templates/actions/settings/blocks/tabs/Design.html`)

Ниже — **каждая настройка**: где показываем, **каким полем** и что означает.

### Zen Mode: общий и пер-инстансный шаблон сводки

В чекауте Shop-Script у каждого **способа доставки** и **способа оплаты** есть свой идентификатор инстанса (несколько подключений одного плагина — разные ID). Для свёрнутой строки группы в Zen Mode задаётся **один общий** Smarty-шаблон на группу (`summary_template`). Дополнительно для отдельных инстансов хранится запись в `custom_templates`: персональный шаблон применяется **только если** у записи включён флаг **«шаблон активен»** (`active`), иначе для этого инстанса всегда используется общий `summary_template` (см. UI ниже).

**Формат хранения (целевой, под UI):** для каждого ID инстанса — объект `{ "active": bool, "template": string }` (Smarty). Сейчас в коде для доставки может фигурировать устаревший вариант «значение = одна строка шаблона» — при внедрении свитчера нужно унифицировать чтение/запись: учитывать `active`, при `false` игнорировать `template`.

- **Доставка** — ключ в `zen.groups.delivery.custom_templates`: строка, которую возвращает `shopPrefillCheckoutState::getShippingInstanceId()`. Это **ID записи способа доставки в `shop_plugin`** (то же значение, что первая часть `variant_id` до точки, формат ключей тарифов в `shopHelper::getShippingMethods()`). **Сверка с ядром Shop-Script (checkout 2.0):** в `shopCheckoutShippingStep::process()` в `data['shipping']['selected_variant']` кладётся элемент из списка тарифов с полем `variant_id` вида `{id_плагина}.{id_тарифа}`; отдельного поля `id` у тарифа ядро не добавляет. В `shopCheckoutDetailsStep` при успешном расчёте выставляется `data['shipping']['id']` = первая часть `variant_id` (переменная `$shop_plugin_id` в коде шага). В `vars` для шаблона шаг shipping отдаёт **`selected_variant_id`**, а не `vars.shipping.selected_variant`. Порядок в геттере: `data.shipping.id` → опционально `data.shipping.selected_variant.id` (кастом плагинов) → первая часть `variant_id` из `getSelectedVariant()` → первая часть `vars.shipping.selected_variant_id`. В норме совпадающие источники дают **одну** строку; метод не сравнивает их попарно.
- **Оплата** — тот же контракт: ID из `getPaymentId()` (`data.payment.id`). В конфиге и в `getSummaryTemplate()` для группы `payment` пер-инстансная логика пока не подключена — добавить по аналогии с доставкой.

#### UI: пер-инстансные шаблоны сводки (доставка и оплата)

**Где:** вкладка Design → блок Zen Mode → группы «Доставка» и «Оплата» (отдельные подсекции или два последовательных списка). Контекст — **текущая витрина** настроек плагина.

**Состав списка:** для витрины подтягиваются **активные** способы доставки и **активные** способы оплаты (инстансы, доступные в магазине для этой витрины). Для каждого инстанса — одна строка настроек.

**Строка инстанса (слева направо):**

1. **Switcher** — «шаблон для этого инстанса активен». В выключенном состоянии персональный шаблон на фронте **не** используется (`active = false` в сохранённых данных).
2. Справа от свитчера — **название инстанса** (как в бекенде Shop-Script: человекочитаемое имя способа доставки/оплаты).

**Под строкой:**

- Свитчер **выкл.** — статичный текст: _используется общий шаблон_ (имеется в виду групповой `summary_template` для доставки или оплаты). Ссылки на редактирование нет.
- Свитчер **вкл.** — ссылка **«Редактировать шаблон»**. Поле с текстом шаблона на самой странице списка **не** показываем — только через модалку.

**Модальное окно «Редактировать шаблон»:**

- **Основная зона (слева или на всю ширину без колонки переменных):** редактор содержимого шаблона. **Сейчас** — одно многострочное текстовое поле (textarea). **Позже** — замена на JS-редактор (подсветка/подсказки Smarty и т.д.) без смены смысла поля.
- **Справа в модалке:** список **доступных переменных** для этой группы (доставка или оплата) — те же плейсхолдеры, что подставляются в Smarty при рендере сводки. Клик по переменной **вставляет** её в редактор (в позицию курсора или в конец — уточнить при реализации).
- Кнопки модалки: сохранить (писать в `template` и не сбрасывать `active`), отмена.

**Итог по данным:** в сохранённом JSON/структуре настроек для каждого инстанса хранятся `active` и `template`; пустой `template` при включённом `active` — решить при реализации (валидация или fallback на общий шаблон).
