# Админ-настройки: шаблоны сводки Дзен-режима

Список всех настроек и их значений по умолчанию — в `lib/config/storefront.settings.php` (по витринам) и `lib/config/settings.php` (общие для плагина). Описание для пользователя — в [../user-guide/ru.html](../user-guide/ru.html). Здесь — только то, чего из кода и пользовательского руководства не видно: контракт хранения шаблонов и граница доступа.

## Zen Mode: общий и пер-инстансный шаблон сводки

В чекауте Shop-Script у каждого **способа доставки** и **способа оплаты** есть свой идентификатор инстанса (несколько подключений одного плагина — разные ID). Для свёрнутой строки группы в Zen Mode задаётся **один общий** Smarty-шаблон на группу (`summary_template`). Дополнительно для отдельных инстансов хранится запись в `custom_templates`: персональный шаблон применяется **только если** у записи включён флаг **«шаблон активен»** (`active`), иначе для этого инстанса всегда используется общий `summary_template` (переключатель у способа во вкладке «Дзен-режим»).

**Формат хранения:** для каждого ID инстанса — объект `{ "active": bool, "template": string }` (Smarty). При `active = false` `template` игнорируется и берётся общий `summary_template`.

- **Доставка** — ключ в `zen.groups.delivery.custom_templates`: строка, которую возвращает `shopPrefillCheckoutState::getShippingInstanceId()`. Это **ID записи способа доставки в `shop_plugin`** (то же значение, что первая часть `variant_id` до точки, формат ключей тарифов в `shopHelper::getShippingMethods()`). **Сверка с ядром Shop-Script (checkout 2.0):** в `shopCheckoutShippingStep::process()` в `data['shipping']['selected_variant']` кладётся элемент из списка тарифов с полем `variant_id` вида `{id_плагина}.{id_тарифа}`; отдельного поля `id` у тарифа ядро не добавляет. В `shopCheckoutDetailsStep` при успешном расчёте выставляется `data['shipping']['id']` = первая часть `variant_id` (переменная `$shop_plugin_id` в коде шага). В `vars` для шаблона шаг shipping отдаёт **`selected_variant_id`**, а не `vars.shipping.selected_variant`. Порядок в геттере: `data.shipping.id` → опционально `data.shipping.selected_variant.id` (кастом плагинов) → первая часть `variant_id` из `getSelectedVariant()` → первая часть `vars.shipping.selected_variant_id`. В норме совпадающие источники дают **одну** строку; метод не сравнивает их попарно.
- **Оплата** — тот же контракт: ID из `getPaymentId()` (`data.payment.id`). В `getSummaryTemplate()` логика для `payment` реализована по той же схеме, что и для `delivery`: если для инстанса задан активный пер-инстансный шаблон — используется он, иначе — общий `summary_template`.

**Модель доступа.** Шаблон — Smarty-строка без песочницы (`enableSecurity()` в Webasyst не включён), т.е. это фактически произвольный PHP-код, а не безопасный текстовый формат. Редактор (и его превью) доступен только администратору магазина (`isAdmin('shop')`) — по возможностям и по уровню доверия он эквивалентен штатному редактору тем Webasyst, не шире. Тот же гейт стоит и на записи (`?module=plugins&action=save`, не только на самом редакторе) — до 09.09.2026 это было не так, см. issue-96. Разбор → [RULES.md B4](RULES.md#границы).
